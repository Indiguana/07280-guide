Recitation 1 — problem formulation, heuristics, ethics

Five problems. The first is pure formulation — turning an informal puzzle into the five-part search problem the algorithms need. The second is the ethics question, which is in scope and which students routinely under-prepare because it has no arithmetic. The rest are admissibility and consistency on small concrete graphs, which is where most of the search marks live.

1.1  Tower of Hanoi

This problem gets a long treatment because search-foundations teaches formulation through Pacman, and Hanoi stresses a completely different part of it: the state representation is a data structure you have to invent, and the state-space count is a combinatorial argument you have to defend. Both show up on exams as standalone parts.

The puzzle

Three pegs. On the first peg sit $n$ disks of distinct sizes, stacked largest at the bottom. A move takes the top disk off any peg and drops it onto any other peg, subject to one rule: a disk may never sit on top of a smaller disk.

Goal: get all $n$ disks onto the third peg.

Problem 1.1Formulate Tower of Hanoi as a search problem

Give all five components: (a) a state representation, (b) the size of the state space as a function of $n$, (c) the start state, (d) the legal actions from an arbitrary state, (e) the goal test.

Number the disks $1, 2, \dots, n$ from smallest to largest. Use $n = 2$ or $n = 3$ to sanity-check anything you are unsure of.

Step 1 — What is actually being asked?

Not "solve the puzzle". You are being asked to produce the input that a generic search algorithm consumes. BFS, DFS, UCS and A* all expect exactly five things and nothing else:

  • a set of states (implicitly, via a representation),
  • an initial state,
  • a successor function: state $\to$ (action, next state, cost) triples,
  • a goal test: state $\to$ true/false,
  • a cost per action (here: 1 per move, so path cost = number of moves).

The grading pressure sits in two places. First, your representation must capture everything that affects the future and nothing else — too little and the successor function is undefined, too much and your state count is wrong. Second, part (b) is a counting argument, and "it's exponential" earns nothing; you need the exact expression and a reason.

Step 2 — (a) Choose a state representation

What does a move depend on? Only which disks are on which peg. Nothing in the rules refers to how you got here, whose turn it is, or how long you have been playing. So a state is exactly a distribution of the $n$ disks across the 3 pegs.

A clean encoding: three ordered lists, one per peg, each listing the disks on that peg from top to bottom.

state = (peg1, peg2, peg3)   e.g. for $n = 3$:   ([1], [3], [2])

That reads: disk 1 alone on peg 1, disk 3 alone on peg 2, disk 2 alone on peg 3.

The observation that makes the count easy

The order within a list is not free information. The no-larger-on-smaller rule means that for any set of disks on a peg, there is exactly one legal order: sorted, smallest on top. So the list is fully determined by the set, and a state is really just a function disk $\to$ peg.

An equivalent and slightly tidier representation: a vector $(p_1, p_2, \dots, p_n)$ where $p_i \in \{1,2,3\}$ is the peg holding disk $i$. The two representations are in bijection; the second is what makes part (b) a one-liner.

Step 3 — (b) Count the state space

Using the vector form: each of the $n$ disks independently sits on one of 3 pegs, and every such choice gives a legal state, because the stacking order is forced.

$|S| = \underbrace{3 \times 3 \times \cdots \times 3}_{n \text{ disks}} = 3^n$

Two things worth saying out loud in an exam answer, because they are where the marks are:

  • Why no factor for ordering. If order within a peg were free, a peg holding $k$ disks would admit $k!$ arrangements and the count would blow up. The constraint kills all but one, so the ordering contributes a factor of 1.
  • Why no illegal states to subtract. Every disk-to-peg assignment is realisable, so $3^n$ is not an over-count that needs trimming.

Check at $n=2$. $3^2 = 9$. Enumerate them, writing each state as peg1 | peg2 | peg3:

Step 4 — (c) Start state and (e) goal test

Start. Everything on peg 1, in forced order:

start = ([1, 2, ..., n], [], [])

Goal test. Everything on peg 3:

goalTest(s) = (s == ([], [], [1, 2, ..., n]))

In the vector form both are one-liners: start is $p_i = 1$ for all $i$; the goal test is $p_i = 3$ for all $i$.

Common mistake

Writing the goal test as "peg 3 has $n$ disks" and stopping. That happens to be equivalent here, but a goal test should be a predicate on the whole state, and a test that reads one peg will silently break the moment you generalise the puzzle (say, to "all disks on peg 2 or peg 3"). Also note there is exactly one goal state, not a set of them — which is unusual, and is why Hanoi has a well-defined notion of "the" optimal solution length.

Step 5 — (d) Legal actions

An action is "move the top disk of peg $i$ onto peg $j$", written $(i \to j)$. In the list representation: pop the front of list $i$ and push it onto the front of list $j$. It is legal when all three conditions hold:

  1. $i \neq j$;
  2. list $i$ is non-empty (there is something to move);
  3. list $j$ is empty, or the front of list $j$ is larger than the disk being moved.

Cost 1 per action, so path cost counts moves.

How many actions are available? There are $3 \times 2 = 6$ ordered peg pairs, but almost all are blocked. Computing the branching factor over every reachable state for $n = 3$ and $n = 4$ gives the same answer both times: at least 2 and at most 3 legal moves from any state. The reasoning: the three exposed disks (one per non-empty peg) have a unique smallest, and that disk can go on either of the other two pegs — so you always have $\ge 2$ moves; and only when all three pegs are non-empty does the middle-sized exposed disk add a third.

So Hanoi is a small-branching, deep search problem: $b \le 3$, and the shallowest goal sits at depth $2^n - 1$ (7 moves for $n=3$, 15 for $n=4$ — both confirmed by breadth-first search over the full state graph). That shape is the opposite of Pacman's, and it is why Hanoi is the standard example for "the state space is small but the tree is not".

Answer — the complete formulation
Statesthree ordered lists (peg1, peg2, peg3) partitioning $\{1,\dots,n\}$, each sorted smallest-first; equivalently a vector $(p_1,\dots,p_n) \in \{1,2,3\}^n$
Size$|S| = 3^n$ — each disk independently on one of 3 pegs; stacking order is forced, so it contributes no factor
Start([1, 2, ..., n], [], [])
Actions$(i \to j)$, $i \neq j$: pop front of list $i$, push onto front of list $j$; legal iff list $i$ non-empty and (list $j$ empty or front of list $j$ $>$ moved disk). Cost 1. Branching factor 2 or 3.
Goal tests == ([], [], [1, 2, ..., n])

Optimal solution length is $2^n - 1$, so the whole state space is reachable and connected: BFS from the start reaches all $3^n$ states for $n = 3$ (27) and $n = 4$ (81).

What this was testing — and where to read more

Technique: search-problem formulation, and in particular the discipline of separating the representation from the count. The exam version of this is almost always "here is a puzzle; give states, start, actions, goal test, and $|S|$".

The transferable move is the one in Step 2: ask what does the successor function actually read? Anything it never reads does not belong in the state. Anything it reads that you left out makes your formulation incomplete. Then ask what does the constraint forbid? — here the stacking rule collapsed $k!$ orderings to 1, and that collapse is the state count.

Read: Chapter 1 — Search problems, BFS/DFS/UCS, especially the state-space-size section. The Pacman formulation there is the same exercise with a different constraint doing the collapsing.

1.2  Ethics warm-up: the crime-avoidance navigation app

This is in scope and it is short-answer, which is a bad combination for students who prepare only the arithmetic. The good news is that short-answer ethics questions are graded on structure, not on reaching a particular verdict. Below is the shape of an answer that earns full marks.

Problem 1.2A navigation app that routes around "high-crime" areas

A navigation app offers a feature that routes drivers around neighbourhoods the app classifies as high-crime, instead of giving the fastest route. The classification is built from crime data and applied automatically to every route.

Answer three things:

  1. If this app became widely used, what effect could it have on businesses inside a flagged area?
  2. Would you want it deployed in your hometown? Give both positive and negative effects for your community.
  3. More generally: how can a classifier like this entrench the disparity it claims only to describe?

Open-ended. There is no single correct verdict — there are answers that identify who is affected and through what mechanism, and answers that do not.

Step 1 — What is actually being asked?

Not "is this app good or bad?". You are being asked to trace consequences through a mechanism. The grading rubric on a question like this rewards three moves, in order:

  1. Name the stakeholders. Not "society" — the specific groups whose situation changes. Here at least: the driver using the app, residents of flagged areas, business owners inside flagged areas, residents of unflagged areas, the app vendor, and whoever produced the crime data.
  2. Name the mechanism. A claim like "this is unfair" with no mechanism is unmarkable. A claim like "fewer cars pass the shop, so the shop loses walk-in revenue" is a mechanism, and it can be argued with.
  3. Say what would change your assessment. What evidence, design change or safeguard would make the system more defensible? This is the move most answers skip and it is often worth the most.

A one-sided answer loses marks even when the side it takes is reasonable, because the question explicitly asks for both.

Step 2 — (1) Effects on businesses inside a flagged area

The direct mechanism is reduced thoroughfare. A business on a street that routing algorithms stop sending cars down loses:

  • Passing trade — the customers who stop because they happened to be driving past. For a petrol station, a takeaway, a corner shop or a car wash, this can be most of the revenue.
  • Discoverability — people never learn the business exists, so the loss compounds over time rather than staying flat.
  • Deliverability and staffing — if navigation defaults route around an area, couriers, contractors and shift workers quietly reprice or decline trips into it.
  • Property and insurance — a publicly visible "avoid" designation is a signal other pricing systems can pick up, independently of whether the underlying risk changed.

Note the asymmetry worth stating explicitly: the business owner is not a party to the decision. The driver chose to use the app and gets a benefit they wanted; the business absorbs a cost it never agreed to and often cannot even observe. That asymmetry — benefit to the chooser, cost to a non-participant — is the standard reason an individually rational feature can be collectively harmful.

Step 3 — (2) Would you deploy it? Both sides, concretely

A full-marks answer gives real items on both sides. The honest positives:

  • Some risk is real and some users face it disproportionately. A night-shift worker, a lone driver unfamiliar with the city, or someone who has been assaulted before may value a route option that is not purely time-optimal. Dismissing that is as weak as ignoring the harms.
  • Perceived safety can increase traffic overall. Visitors who would otherwise avoid an unfamiliar city entirely may travel more, which is an economic gain — though note it accrues to the unflagged areas.
  • Transparency about risk is not inherently wrong. Public crime statistics already exist; an app that surfaces them is not inventing information.

The negatives:

  • Concentrated economic harm, as in Step 2, falling on areas that already have less economic slack to absorb it.
  • Disparate impact. In most US cities, areas with high recorded crime rates correlate strongly with historical patterns of residential segregation and disinvestment. So a feature that is written with no reference to race or income can still redistribute traffic and revenue along race and income lines. The code does not need to mention a protected attribute to act on it — a proxy is enough.
  • Reputational harm that is hard to reverse. Being labelled is sticky; coming off the list requires the statistics to move, which requires the investment the label discourages.
  • Residents of flagged areas are also users. They get an app that tells them their own neighbourhood is to be avoided.

A defensible verdict can go either way — "deploy with changes" is usually the strongest answer, because it forces you to name the changes. Plausible safeguards to name: make it opt-in and off by default rather than applied to every route; operate at street-and-time granularity rather than labelling whole neighbourhoods; use incident types relevant to a person in a moving car rather than all recorded crime; publish the classification so affected businesses can contest it; and audit the routing output for disparate impact rather than only auditing the inputs.

Step 4 — (3) The feedback loop, drawn explicitly

This is the part that connects the question to the rest of the course, and it is the part worth memorising as a pattern, because it recurs in predictive policing, credit scoring, hiring filters and content ranking.

recorded crime $\to$ area classified "avoid" $\to$ traffic and revenue fall $\to$ businesses close, investment leaves $\to$ conditions worsen $\to$ recorded crime rises $\to$ classification confirmed

Three properties of this loop are worth stating:

  • It is self-confirming. The model's prediction changes the world in the direction of the prediction, so the model looks increasingly accurate because it was deployed. Accuracy measured after deployment is therefore not evidence that the classification was correct beforehand.
  • The measurement is not neutral. "Recorded crime" is a record of reports and enforcement, not of crime. Areas that are policed more heavily record more crime at the same underlying rate, so the input already carries the history of how policing was allocated.
  • Describing and causing are not separable once you act on the description. A classifier that is never used is a description. A classifier wired into millions of route decisions is an intervention, and it inherits responsibility for the outcomes it produces.

This is the general shape: a classifier trained on a record of past treatment, deployed in a way that affects future treatment, converges on justifying the past treatment.

Answer & the takeaway — what a strong exam answer looks like

A full-credit answer, compressed to exam length, does this:

  1. Businesses: lose passing trade and discoverability as routing traffic falls; harm is concentrated and lands on parties who did not choose the feature and cannot observe it.
  2. Positives: genuine safety value to some users, especially unfamiliar or vulnerable drivers; possible increase in overall travel from higher perceived safety.
  3. Negatives: concentrated economic harm; disparate impact via a proxy, with no protected attribute in the code; sticky reputational damage; residents of flagged areas are harmed by a product aimed at them.
  4. Mechanism: the self-confirming feedback loop in Step 4, plus the point that recorded crime measures enforcement as well as crime.
  5. Position: a clear verdict with named safeguards — opt-in, finer granularity, relevant incident types, contestable and published classifications, output auditing for disparate impact.
Common mistake

Three ways to lose marks here. One: writing only one side when the question asks for both. Two: asserting harm without a mechanism — "this is discriminatory" is a conclusion, not an argument; the argument is the proxy-plus-feedback-loop chain. Three: answering as if the only question were the model's accuracy. A perfectly accurate classifier of recorded crime can still produce every harm above, which is exactly why "is it accurate?" and "is it defensible to deploy?" are different questions.

Technique: stakeholder-and-mechanism analysis of a deployed classifier, plus recognising a feedback loop between prediction and outcome. The closest formal material on the site is the discussion of what a model is actually trained on, and the gap between training distribution and deployment distribution, in Chapter 5 — ML problem formulation; the "accuracy is not the only objective" thread continues in Chapter 12.

Problem 1.3Admissible, consistent, and the implication between them

Use the graph in Figure 2: undirected edges S–A = 5, S–B = 3, A–C = 4, A–D = 9, C–D = 2, C–G = 6, B–D = 1, D–G = 4. Start S, goal G.

Step 1 — What is actually being asked?

Part 3 is the whole problem. Parts 1, 2 and 4 exist to make part 3 possible, because you cannot construct a counterexample to an implication until you know exactly which inequality each property is.

Before anything else, compute the one quantity both definitions refer to: $h^*(n)$, the true cheapest cost from $n$ to the nearest goal. Everything is measured against it, and in an exam you will be given a small enough graph to just read these off.

  • $h^*(\text{B}) = 1 + 4 = 5$ via B–D–G.
  • $h^*(\text{A}) = 10$: A–C–G is $4+6=10$, A–C–D–G is $4+2+4=10$, A–D–G is $9+4=13$. So 10.
  • $h^*(\text{S}) = 8$ via S–B–D–G $= 3+1+4$. Going through A costs $5 + 10 = 15$.

So the optimal solution is S → B → D → G with cost 8. Any correct heuristic must let A* find that.

Step 3 — (1) The two definitions, stated precisely
Admissible

$h$ is admissible if it never overestimates the true remaining cost: $$0 \le h(n) \le h^*(n) \quad \text{for every node } n.$$ It is a statement about each node in isolation, comparing $h(n)$ against the goal.

Consistent

$h$ is consistent if for every edge from $n$ to $n'$ with cost $c(n, n')$: $$h(n) \le c(n, n') + h(n').$$ Equivalently $h(n) - h(n') \le c(n,n')$: the heuristic's estimate of a single step never exceeds that step's real cost. It is a statement about each edge.

The difference in one line: admissibility is a global condition checked per node against the goal; consistency is a local condition checked per edge against a neighbour. That is why consistency is strictly stronger — it constrains how fast $h$ is allowed to change as you walk, not just where it ends up.

Step 4 — (2) What path does A* return?

A* always expands the frontier node with the smallest $f(n) = g(n) + h(n)$, where $g$ is the cost already paid and $h$ is the estimate of what remains. Two reference choices:

  • Zero heuristic, $h \equiv 0$. Then $f = g$ and A* is literally uniform-cost search. It returns S–B–D–G, cost 8, after expanding essentially everything cheaper than 8.
  • Exact heuristic, $h = h^*$. Then $f(n) = 8$ at every node on an optimal path and $f(n) > 8$ off it, so A* walks straight down S–B–D–G with no wasted expansions. This is the best any heuristic can do.

Both are admissible, so both return the optimal path — and that is the point of the question. The heuristic does not change which path an optimal algorithm returns; it changes how much of the graph you had to look at to be sure. (The exact heuristic is also consistent, as Figure 2's report confirms for every edge; the zero heuristic trivially is.)

Step 5 — (3) Build an admissible, inconsistent heuristic

The recipe, once you have the two definitions side by side: admissibility only caps each value from above, so you are free to make $h$ very accurate at one node and very bad at its neighbour. A big drop across a cheap edge breaks the local inequality while leaving every global cap satisfied.

Step 6 — (4) Prove consistency $\Rightarrow$ admissibility

Assume $h$ is consistent and $h(n_g) = 0$ at every goal. We must show $h(n) \le h^*(n)$ for all $n$.

The idea first

Consistency bounds how much $h$ can fall per step. Walk the optimal path from $n$ to the goal and add up those per-step bounds: the total fall is at most the total cost. But the total fall is $h(n) - 0 = h(n)$, and the total cost is $h^*(n)$. The proof is just that telescoping sum, written carefully.

Setup. Fix a node $n$ and let $n = n_0 \to n_1 \to \cdots \to n_k = n_g$ be a cheapest path from $n$ to its nearest goal, so that $$h^*(n) = \sum_{i=0}^{k-1} c(n_i, n_{i+1}).$$

Induction on $k$, the number of edges remaining.

Base case $k = 0$. Then $n$ is itself a goal, $h(n) = 0 = h^*(n)$, so $h(n) \le h^*(n)$. ✓

Inductive hypothesis. Suppose the claim holds for every node whose nearest goal is reachable in $k-1$ optimal steps: in particular $h(n_1) \le h^*(n_1)$.

Inductive step. Consistency on the single edge $n_0 \to n_1$ gives $$h(n_0) \le c(n_0, n_1) + h(n_1).$$ Apply the hypothesis to $h(n_1)$: $$h(n_0) \le c(n_0, n_1) + h^*(n_1).$$ Now use the fact that the path was optimal. Because $n_0 \to n_1 \to \cdots \to n_g$ is a cheapest path from $n_0$, its tail is a cheapest path from $n_1$, so $$c(n_0, n_1) + h^*(n_1) = h^*(n_0).$$ Substituting, $h(n_0) \le h^*(n_0)$. ■

Written as the telescoping sum instead, the same argument in one line: adding $h(n_i) - h(n_{i+1}) \le c(n_i, n_{i+1})$ over $i = 0, \dots, k-1$ gives $$h(n_0) - \underbrace{h(n_k)}_{=\,0} \le \sum_{i=0}^{k-1} c(n_i,n_{i+1}) = h^*(n_0).$$

Where this proof is usually botched

Two places. One: forgetting to say the path is optimal. Along an arbitrary path the telescoping sum only gives $h(n) \le (\text{that path's cost})$, which is a weaker statement; you need the optimal path for the right-hand side to be $h^*$. Two: forgetting the assumption $h(\text{goal}) = 0$. Without it the base case fails and the whole thing collapses — $h \equiv 100$ on a graph with all edge costs 0 is "consistent" edge-by-edge and wildly inadmissible.

The converse is false, which is what Step 5 constructed. So consistent $\Rightarrow$ admissible, and the implication is strict.

What this was testing — and where to read more

Technique: the admissibility/consistency distinction, and the ability to construct a counterexample to a one-directional implication. The exam version is usually "is this heuristic admissible / consistent / neither, and justify" — which you answer by checking one inequality per node for admissibility and one inequality per edge for consistency. There is no shortcut and there does not need to be; these graphs are small.

The reason the distinction is worth marks at all: admissibility is enough for A* tree search to be optimal, but graph search (with an explored set) needs consistency. Problem 1.5(f) below is a concrete graph where admissible-but-inconsistent makes A* graph search return a suboptimal path.

Problem 1.4Run DFS, BFS, UCS, Greedy and A* on the same graph

Graph as in Figure 3. Directed edges with costs: A→C 2, A→D 1, A→E 3, C→F 2, C→G 3, D→G 1, F→B 1, B→C 1. Heuristics: $h$(A)=2, $h$(B)=2, $h$(C)=1, $h$(D)=1, $h$(E)=0, $h$(F)=3, $h$(G)=0. Start A; goals E and G.

For each of DFS, BFS, UCS, Greedy, A*, run graph search and report (i) the nodes added to the explored set, in order, and (ii) the path returned and its cost. Break ties alphabetically when popping from the frontier. A node is tested for goalhood when it is popped, not when it is generated, and it enters the explored set only if it is not a goal.

Step 1 — What is actually being asked?

Not "find the best path" — the point is to watch five different frontier orderings produce five different behaviours on identical data. Three conventions decide every answer, so pin them down first:

  • Goal test on pop, not on generation. This is why Greedy's explored set contains only A: E gets generated, then popped, and the search stops before E is ever "explored".
  • Graph search: there is an explored set, and a node already explored is never expanded again.
  • Alphabetical tie-breaking on the frontier, applied after the algorithm's own priority.

The frontier priority for each: DFS = deepest first; BFS = shallowest first; UCS = smallest $g$; Greedy = smallest $h$; A* = smallest $g + h$.

Step 2 — DFS

Pop A (not a goal) → explored {A}. Children: C, D, E, all at depth 1. Deepest-first with alphabetical tie-break pops C.

C is not a goal → explored {A, C}. Children F, G at depth 2. Deepest first, alphabetical: pop F.

F not a goal → explored {A, C, F}. Child B at depth 3. Pop B (deepest).

B not a goal → explored {A, C, F, B}. B's only child is C, already explored, so nothing is added. The frontier now holds A-C-G (depth 2), A-D (depth 1), A-E (depth 1). Deepest is G — a goal. Stop.

Explored: A, C, F, B   ·   Path: A → C → G   ·   cost 5

DFS dove into a dead-end branch (F, B) that leads nowhere new, and returned a path costing 5 when a cost-2 path existed. It also never looked at D, which is on the optimal path.

Step 3 — BFS

Pop A → explored {A}; frontier C, D, E all at depth 1. Shallowest first, so the whole of depth 1 goes before any of depth 2; alphabetical within the level.

Pop C (not a goal) → explored {A, C}; adds F, G at depth 2.

Pop D (not a goal) → explored {A, C, D}; adds G at depth 2.

Pop E — a goal, at depth 1. Stop.

Explored: A, C, D   ·   Path: A → E   ·   cost 3

BFS found the shallowest goal, exactly as advertised: one edge. Shallowest is not cheapest — cost 3 against the optimum of 2. This is the cleanest one-line demonstration on the page that BFS optimises depth, not cost.

Step 4 — UCS

Pop A at $g=0$ → explored {A}. Frontier by $g$: D 1, C 2, E 3.

Pop D ($g=1$, not a goal) → explored {A, D}; adds A-D-G at $g = 1 + 1 = 2$.

Frontier: C 2, G 2, E 3. Tie at 2 between C and G — alphabetical, so pop C (not a goal) → explored {A, D, C}; adds F at $g=4$ and a second route to G at $g=5$ (worse, discarded).

Frontier: G 2, E 3, F 4. Pop G at $g=2$ — a goal. Stop.

Explored: A, D, C   ·   Path: A → D → G   ·   cost 2

Optimal, as UCS always is with non-negative costs. Note it paid for that with one extra expansion (C) that A* will avoid.

Step 5 — Greedy, then A*

Greedy best-first orders the frontier by $h$ alone, ignoring $g$ entirely.

Pop A → explored {A}. Frontier with $h$: C 1, D 1, E 0. Smallest $h$ is E. Pop E — a goal. Stop.

Explored: A   ·   Path: A → E   ·   cost 3

One expansion — the cheapest search on the page — and a suboptimal answer, cost 3 against 2. Greedy took the bait: E is a goal and $h(\text{E}) = 0$, but reaching it costs 3 while D's cheaper route costs 2 in total. Greedy cannot see that because it never looks at $g$.

A* orders by $f = g + h$.

Pop A ($f = 0+2 = 2$) → explored {A}. Frontier: C $f = 2+1 = 3$, D $f = 1+1 = 2$, E $f = 3+0 = 3$.

Pop D ($f = 2$, not a goal) → explored {A, D}; adds G at $f = 2 + 0 = 2$.

Frontier: C 3, E 3, G 2. Pop G at $f = 2$ — a goal. Stop.

Explored: A, D   ·   Path: A → D → G   ·   cost 2

Optimal and cheaper than UCS — 2 expansions instead of 3, because $h$ told it that C was not worth opening.

1.5  True/false batch: search and heuristics

Problem 1.5Six true/false claims, each needing a justification or a counterexample

Decide true or false, and give a one-line reason or a concrete counterexample. Writing just "false" earns nothing.

  1. DFS always expands at least as many nodes as A* with an admissible heuristic.
  2. A rook moves any number of squares in a straight line, horizontally or vertically, and cannot jump pieces. Manhattan distance is an admissible heuristic for the minimum number of rook moves from square A to square B.
  3. Euclidean distance is an admissible heuristic for Pacman path-planning.
  4. The sum of several admissible heuristics is admissible.
  5. Admissibility implies consistency.
  6. A* with graph search is always optimal given an admissible heuristic.
Step 1 — What is actually being asked?

Each item is an "always" claim, so there are only two kinds of correct answer: a proof that it holds in general, or a single concrete instance where it fails. Four of these six are false, and for each of those a three-node graph is enough. Learning to reach for the smallest possible counterexample is the skill being tested.

Watch for the two words that make a claim fragile: "always" and "implies". Both are universally quantified, so one example kills them.

Step 2 — (a) DFS vs A* node counts

False.

DFS has no guarantee of expanding many nodes — it has no guarantee at all. If the goal happens to lie at the end of the first branch DFS picks, it expands exactly the $d$ nodes on that path and stops. Meanwhile A*, being complete and optimal, must expand every node whose $f$-value is strictly less than the optimal cost before it can certify the answer. If several such nodes exist off the lucky branch, A* expands more.

Problem 1.4 above is almost this: Greedy expanded 1 node, A* expanded 2, and Greedy's answer was worse. The general statement: being optimal costs work, and a lucky unguided search can beat a correct guided one on any single instance. What A* guarantees is the answer, not a node-count bound against DFS.

Step 3 — (b) Manhattan distance for a rook

False. Manhattan distance overestimates, which is the direction admissibility forbids.

Counterexample: on an empty board, a rook goes from one corner to the opposite corner of a $4 \times 4$ region in 2 moves (along a row, then along a column). Manhattan distance between those squares is $3 + 3 = 6$. Since $6 > 2$, the heuristic overestimates and is not admissible.

The reason is a units mismatch: Manhattan distance counts squares travelled, but the cost function counts moves, and one rook move covers arbitrarily many squares. An admissible heuristic here is the far cruder "0 if same square, 1 if same row or column, else 2" — and on an empty board that is exact. Whenever a heuristic looks wrong, check first whether it is measuring the same thing the cost function charges for.

Step 4 — (c) Euclidean distance for Pacman

True.

Pacman moves on a grid, one square per unit cost, only horizontally or vertically. A straight line is the shortest distance between two points in the plane, so the Euclidean distance can never exceed the length of any route — in particular it cannot exceed the shortest legal grid route. Hence $0 \le h(n) \le h^*(n)$.

The two cases, explicitly:

  • Goal in the same row or column, no walls: Euclidean distance equals the true cost. Tight, still admissible.
  • Goal diagonally offset: Euclidean distance is $\sqrt{\Delta x^2 + \Delta y^2}$, strictly less than the grid cost $\Delta x + \Delta y$. A loose underestimate.

Walls only ever make the true cost larger, which widens the gap and keeps admissibility. The general pattern: relaxing the problem until it is trivially solvable gives an admissible heuristic — here the relaxation is "let Pacman fly in a straight line through walls".

Step 5 — (d) Sum of admissible heuristics

False. Two underestimates can easily add up to an overestimate.

Counterexample on a 3-node path graph, S → A cost 4, A → B cost 6, goal B:

But the maximum is safe: $\max(h_1, h_2) \le h^*$ whenever both are, since the max of two numbers each $\le h^*$ is $\le h^*$. So when you have several admissible heuristics, take the max, never the sum — and note the max is at least as informative as either one, so this is a free improvement. (Sums are admissible in the special case where the heuristics are disjoint, i.e. each accounts for cost the others do not; that is how pattern databases are combined, and it is a property you have to prove, not assume.)

Step 6 — (e) Admissibility implies consistency

False. The implication runs the other way only — see the proof in Problem 1.3, Step 6.

Smallest counterexample: path graph S → A cost 1, A → B cost 3, goal B.

Admissible: $4 \le 4$, $1 \le 3$, $0 \le 0$. Inconsistent on the edge S → A: we need $h(\text{S}) \le c(\text{S},\text{A}) + h(\text{A})$, i.e. $4 \le 1 + 1 = 2$. It fails.

Read it as a sentence: the heuristic claims 4 units remain at S and only 1 unit remains at A, so it claims 3 units of progress were made — across an edge that cost 1. The heuristic's step estimate $h(\text{S}) - h(\text{A}) = 3$ overestimates the real step cost of 1. The triangle inequality is violated, and Problem 1.3 Step 5 is the same trick on a bigger graph.

Step 7 — (f) A* graph search with an admissible heuristic

False, and this is the item worth the most, because it is the reason consistency exists as a concept at all.

Counterexample. Four nodes, goal C, edges S→A 1, S→B 3, A→B 1, B→C 2. Heuristics $h(\text{S}) = 4$, $h(\text{A}) = 3$, $h(\text{B}) = 0$, $h(\text{C}) = 0$.

First, admissibility: true costs to C are $h^*(\text{S}) = 4$ (via S-A-B-C $= 1+1+2$), $h^*(\text{A}) = 3$, $h^*(\text{B}) = 2$, $h^*(\text{C}) = 0$. So $4 \le 4$, $3 \le 3$, $0 \le 2$, $0 \le 0$ — admissible. The optimal path is S → A → B → C, cost 4.

Now run A* graph search:

  1. Pop S. Frontier: S-A with $f = 1 + 3 = 4$; S-B with $f = 3 + 0 = 3$.
  2. Smallest $f$ is 3, so pop B at $g = 3$ and mark B explored. Adds B-C at $f = 5 + 0 = 5$.
  3. Frontier: A $f=4$, C $f=5$. Pop A at $g = 1$. A's successor is B — but B is already in the explored set, so the edge A→B is discarded and the cheaper route to B at $g = 2$ is never recorded.
  4. Frontier: C $f = 5$. Pop C. Return S → B → C, cost 5.

Cost 5, not 4. A* graph search returned a suboptimal path with an admissible heuristic.

The mechanism, stated so you can recognise it: $h(\text{B}) = 0$ was a severe underestimate, which pulled B's $f$-value down and got B popped early via an expensive route. The explored set then froze that mistake in place. Checking consistency confirms the diagnosis — the edge A→B requires $h(\text{A}) \le c(\text{A},\text{B}) + h(\text{B})$, i.e. $3 \le 1 + 0 = 1$, which fails.

The rule to memorise

A* tree search is optimal with an admissible heuristic. A* graph search needs a consistent one. The reason is exactly the step above: graph search commits to the first $g$ it records for a node, and only consistency guarantees that the first time a node is popped, it is popped with its optimal $g$.

Step 1 — What is actually being asked, and the two rules

You are being asked to simulate a recursion, so the only way to get it right is to be strict about what $\alpha$ and $\beta$ mean:

  • $\alpha$ = the best (highest) value MAX can already guarantee somewhere on the path from the root to the current node. It starts at $-\infty$ and only ever increases, and only at MAX nodes.
  • $\beta$ = the best (lowest) value MIN can already guarantee on that path. Starts at $+\infty$, only decreases, only at MIN nodes.

Each rule says the same thing in different voices: "the player above me already has an option at least this good, so nothing I find here can change their mind."

B₂ (MAX), inherits $(\alpha, \beta) = (-\infty, 5)$ — note it gets B's updated $\beta$, which is the whole point. Reads 6: $v = 6$, $\alpha \leftarrow 6$. Check the cutoff: $v = 6 \ge \beta = 5$, so prune — the second leaf (value 2) is never read. Returns 6, with $\alpha = 6, \beta = 5$.

Back at B: $v = \min(5, 6) = 5$, $\beta = 5$. B returns 5 with $(\alpha, \beta) = (-\infty, 5)$. Root: $v = 5$, $\alpha \leftarrow 5$.

2.2  True/false: minimax value versus expectimax value

Problem 2.2Replace every minimizer with a chance node — what happens to the value?

Take a game tree whose root is a maximizer, and let $V_M$ be its minimax value. Now build a second tree, identical except that every MIN node is replaced by a chance node with some known but arbitrary probability distribution over its children. Let $V_E$ be the expectimax value of that second tree.

  1. $V_M \le V_E$ is guaranteed.
  2. Playing the minimax optimal policy in the chance game guarantees a payoff of at least $V_E$.
Step 1 — What is actually being asked?

Both items compare two numbers computed from two trees, and (b) adds a third thing: a policy transplanted between them. Keeping those three ideas separate is the whole problem. Specifically distinguish:

  • the value of a tree — what you get if you play optimally against that particular opponent model;
  • the policy — the move you choose at each node;
  • what a guarantee means — a worst-case floor, versus an average.
Step 2 — (a) Is $V_M \le V_E$?

True.

The argument is a single inequality applied bottom-up. At any node that was a MIN node and is now a chance node with children values $v_1, \dots, v_m$ and probabilities $p_1, \dots, p_m$:

$\displaystyle \min_i v_i \;\le\; \sum_i p_i v_i$

because a weighted average of numbers (weights non-negative, summing to 1) can never fall below the smallest of them. So replacing MIN with expectation weakly increases the value at that node. MAX is monotone — raising a child's value can only raise or hold the max — so the increase propagates up the tree without reversing. Hence $V_M \le V_E$.

In words: minimax assumes the worst possible opponent. A randomising opponent is, by definition, no worse than the worst. Playing against a weaker opponent can only help you. Equality happens exactly when every chance node puts all its probability on its own minimum child — i.e. when the "random" opponent is in fact playing optimally against you.

Step 3 — (b) Does the minimax policy guarantee $V_E$?

False, and for two independent reasons. Either one is enough to answer.

Reason 1 — the minimax policy is the wrong policy for the chance game. Minimax chooses the action whose worst case is best, so it will refuse an action with a catastrophic but unlikely branch. Expectimax chooses the action whose average is best, so it takes that gamble when the average pays. Those are different actions in general, and $V_E$ is by definition the value of the expectimax policy. Playing a different policy gets you the value of that policy, which is at most $V_E$ and typically strictly less.

Concretely: offered a guaranteed 1, or a coin flip between 100 and $-1$, minimax takes the guaranteed 1 (worst cases 1 versus $-1$) while expectimax takes the flip (expected value 49.5). The expectimax value of the tree is 49.5; the minimax policy delivers 1.

Reason 2 — "at least" is the wrong kind of claim about an expectation. Even if you did play the expectimax policy, $V_E$ is an average over the chance outcomes. On any single playthrough you can land on a bad branch and score far below $V_E$. An expectation is not a floor. Minimax values are floors (that is what makes them guarantees); expectimax values are not.

So the claim fails both on which policy and on what kind of promise a value is.

Answer & the takeaway

(a) True — $\min \le$ weighted average, applied at every converted node and propagated through monotone MAX.

(b) False — the minimax policy is risk-averse and so generally differs from the expectimax policy; and in any case an expectation is not a worst-case guarantee.

The sentence to carry

Minimax gives you a floor. Expectimax gives you an average. Swap the opponent model and you must swap the policy too — and when you move from minimax to expectimax you also give up the right to say "at least".

Technique: reasoning about values versus policies, and about the difference between worst-case and expected-case guarantees. Read: Chapter 3, the expectimax section.

Problem 2.3Evaluate an expectimax tree, then prune it given leaf bounds

The root is a MAX node with two chance children, P and Q. Visit left to right.

  • P has probabilities $\tfrac12, \tfrac12$ over two MAX nodes: P₁ with leaves $[14, 6]$, P₂ with leaves $[2, 10]$.
  • Q has probabilities $\tfrac34, \tfrac14$ over two MAX nodes: Q₁ with leaves $[3, -5]$, Q₂ with leaves $[8, 1]$.

(a) Compute the value at every internal node. (b) Could any node have been pruned? (c) Now suppose you are told every leaf lies in $[-20, 20]$. Re-solve, pruning whatever you can.

Step 1 — What is actually being asked?

Part (a) is mechanical. Parts (b) and (c) are the real question, and they are about one idea: pruning requires a bound.

At a MIN node you get a bound for free — one child's value already caps the node, because MIN will take at most that. At a chance node you get nothing for free: the node's value is an average, and until you have seen every child, any unseen child could be arbitrarily large and drag the average arbitrarily high. So a chance node is only prunable when something external caps the unseen children. That external thing is the leaf bound in part (c).

Expectimax values are computed child-by-child, so for each node: multiply each child's value by its probability and add.

Step 2 — (a) Values at every node

Bottom up. The MAX nodes just take maxima:

NodeLeavesValue
P₁14, 6$\max = 14$
P₂2, 10$\max = 10$
Q₁3, $-5$$\max = 3$
Q₂8, 1$\max = 8$

Then the chance nodes take expectations:

$P = \tfrac12 (14) + \tfrac12 (10) = 7 + 5 = \mathbf{12}$

$Q = \tfrac34 (3) + \tfrac14 (8) = \tfrac94 + 2 = \tfrac{17}{4} = \mathbf{4.25}$

And the root is a maximizer: $\max(12, 4.25) = \mathbf{12}$, choosing P.

Note that no node here is a minimizer. The value 12 is therefore not a guarantee — play P and you get 14 or 10, each half the time, averaging 12. The specific number 12 never actually occurs.

Step 3 — (b) With unbounded leaves, can anything be pruned?

No. Not a single node.

Here is the argument, and it is worth being able to state it crisply because it is the standard exam answer.

Suppose we have finished P (value 12) and are partway through Q, having evaluated Q₁ $= 3$. Can we skip Q₂? Only if we can show $Q \le 12$ without looking. But

$Q = \tfrac34(3) + \tfrac14 (\text{Q}_2) = 2.25 + 0.25\,\text{Q}_2$

and if Q₂ is unbounded above then so is $Q$. Setting $Q$'s leaf 8 to, say, $10^6$ would make $Q = 250{,}002.25$ and change the root's answer. Since nothing in the problem rules that out, we are obliged to look.

The same reasoning blocks pruning inside the MAX nodes: at P₁, after reading 14, we cannot skip the second leaf, because a MAX node needs a $\beta$ from above to cut against — and there is no minimizer anywhere in this tree, so $\beta$ is $+\infty$ everywhere.

Why chance nodes resist pruning

At a MIN node, one child's value is already an upper bound on the node: whatever else is there, MIN will not choose worse-for-MIN than what it has. At a chance node there is no choice to exploit — the node is forced to average everything, so every unseen child still moves the answer. Unseen children at a MIN node are optional; at a chance node they are mandatory.

This is why alpha-beta has no direct expectimax analogue, and why game-playing programs that face randomness (backgammon, poker) lean on sampling and evaluation functions rather than on exact pruning.

Step 4 — (c) Now leaves are bounded by $[-20, 20]$

The bound is what unlocks pruning: an unseen subtree can now be no better than $+20$, so a partial expectation gives a genuine optimistic ceiling.

Visit left to right.

P: Can we prune inside P? After P₁ $= 14$, the optimistic ceiling on P is $\tfrac12 (14) + \tfrac12 (20) = 17$. We have no better alternative banked yet ($\alpha = -\infty$ at the root), so 17 beats nothing and we must continue. P₂ $= 10$, and $P = 12$. Root banks $\alpha = 12$.

Q: Evaluate Q₁ $= 3$ (both its leaves, since there is nothing to cut against inside it). Now compute Q's optimistic ceiling, assuming the unseen Q₂ comes back at the maximum possible $+20$:

$Q \;\le\; \tfrac34(3) + \tfrac14(20) \;=\; 2.25 + 5 \;=\; \mathbf{7.25}$

And $7.25 \le \alpha = 12$. So prune Q₂ — the MAX node and both its leaves (8 and 1) are never visited. Q returns the bound 7.25 rather than its true value 4.25, which does not matter because both are below 12.

Root returns 12, choosing P. 6 of 8 leaves were read.

Notice how fragile this is, and drag the slider in Figure 5 to feel it. The prune needs $\tfrac34(3) + \tfrac14 M \le 12$, i.e. $M \le 39$. With leaves bounded by $\pm 40$ instead of $\pm 20$, the ceiling is $2.25 + 10 = 12.25 > 12$ and nothing gets pruned. And the $\tfrac14$ weight is doing much of the work: if Q's probabilities were $\tfrac12, \tfrac12$ the ceiling at $M = 20$ would be $11.5$ — still a prune, but only just. The tighter the bound and the smaller the unseen probability mass, the more you can prune.

Answer & the takeaway

(a) P₁ $=14$, P₂ $=10$, Q₁ $=3$, Q₂ $=8$; chance nodes $P = 12$, $Q = 4.25$; root $= 12$, choosing P.

(b) Nothing is prunable. Unbounded leaves mean an unseen child of a chance node can be arbitrarily large, so no partial expectation bounds the node; and with no MIN node anywhere, $\beta = +\infty$ throughout, so the MAX nodes have nothing to cut against either.

(c) With leaves in $[-20, 20]$: after Q₁ $= 3$, the ceiling on Q is $7.25 \le 12$, so Q₂ and its two leaves are pruned. Root still 12; 6 of 8 leaves read.

Takeaway. Pruning is not a property of an algorithm, it is a property of information. Alpha-beta prunes because MIN and MAX hand each other bounds for free. Chance nodes hand out nothing, so expectimax prunes only when you are given a bound from outside — and then only by exactly as much as the bound is tight.

Technique: expectimax evaluation and bound-based pruning at chance nodes. Read: Chapter 3, the expectimax and pruning sections.

2.4  Discussion: forward checking vs AC-3, and why MRV and LCV

Problem 2.4Three short-answer questions on CSP machinery

(a) What is the difference between forward checking and AC-3?

(b) Why would you use MRV (minimum remaining values)?

(c) Why would you use LCV (least constraining value)?

Step 1 — What is actually being asked?

These look like definition recall and they are not. Each has a one-sentence answer that earns full marks, and a longer answer that earns full marks and also predicts the next exam question. The one-sentence versions:

  • (a) Same operation, different scope: forward checking enforces arc consistency once, only on the arcs into the just-assigned variable; AC-3 keeps going until nothing changes anywhere.
  • (b) MRV answers "which variable next?" and the answer is "the one most likely to fail", because failing early prunes more.
  • (c) LCV answers "which value first?" and the answer is "the one most likely to succeed", because you only need one solution.

Notice that MRV and LCV point in opposite directions — one seeks failure, the other avoids it. That is the single most commonly misstated thing about them, so Step 4 explains why it is not a contradiction.

Step 2 — (a) Forward checking vs AC-3

Both do the identical primitive operation, revise an arc: for a directed arc $X \to Y$, delete from $D_X$ every value with no consistent partner left in $D_Y$. Values die in the tail. They differ only in which arcs they revise and when they stop.

Forward checkingAC-3
Triggeryou just assigned $X$called explicitly (before search, or after an assignment)
Arcs revisedonly $Y \to X$ for each unassigned neighbour $Y$ of $X$ — one layerstarts from a queue of arcs and re-adds $Z \to Y$ for every neighbour $Z$ whenever $D_Y$ shrinks
Stops whenthat one layer is donethe queue is empty: no arc anywhere can delete anything

So: forward checking is one iteration of AC-3's inner loop, with no propagation. AC-3 propagates.

The consequence that exams test: forward checking can miss a failure that is already logically certain. If two neighbouring variables both get reduced to the same single value, the problem is dead — but forward checking only ever looks outward from the assigned variable, so it never compares those two neighbours with each other and reports no failure. AC-3 would revise the arc between them and empty a domain. Chapter 4 works a concrete instance of exactly this.

Step 3 — (b) Why MRV?

MRV = choose the unassigned variable with the fewest remaining legal values. Also called "most constrained variable", and informally fail-fast.

Two justifications, and a good answer gives both:

  • You have to assign every variable anyway. Unlike path search, there is no choice about which variables appear in the answer — all $n$ of them do, and every solution sits at depth $n$. So the ordering is free: it costs nothing to do the hard ones first. Given that it is free, do the thing that helps.
  • Failing early prunes exponentially more. A variable with 1 remaining value has branching factor 1; a variable with $d$ has branching factor $d$. Putting the small branching factors near the root of the search tree makes the whole tree smaller. And if a variable has zero remaining values, MRV finds that immediately and you backtrack at depth $k$ instead of discovering it at depth $n$ after $d^{\,n-k}$ wasted assignments.

The slogan: if this branch is doomed, I want to know now, not after I have filled in the easy variables.

Step 4 — (c) Why LCV, and why it is not the opposite mistake

LCV = among the values left for the chosen variable, try the one that rules out the fewest values in neighbouring domains. In practice: for each candidate value, run forward checking, sum the sizes of the neighbours' surviving domains, and pick the value with the largest sum.

The justification: we only need one solution, and we are not going to try all $d^n$ combinations. So the value we try first should be the one most likely to lead somewhere — and "leaves the most options open downstream" is a decent proxy for that. If it works, we never try the others at all.

Why MRV and LCV pull in opposite directions — and both are right

They answer different questions about different objects.

Variables are not optional. Every one must be assigned, on every branch. So for variables, the useful question is "where will I find out I am wrong?" and the answer is as early as possible → pick the most constrained variable.

Values are optional. Only one value per variable survives into the answer, and the others are never needed if the first one works. So for values, the question is "which one will work?" and the answer is whichever keeps the most doors open → pick the least constraining value.

One honest caveat: LCV is a heuristic in the weak sense, and it costs real work to evaluate (one forward-checking pass per candidate value). On problems with no solution it is pure overhead, since every value fails and the ordering is irrelevant. MRV, by contrast, helps on satisfiable and unsatisfiable instances alike. Problem 2.7 below measures both on a tiny instance.

Answer & what this was testing

(a) Same revise operation; forward checking does one layer (arcs into the just-assigned variable) and stops, AC-3 propagates to a fixpoint over the whole graph. FC is cheap and can miss already-certain failures; AC-3 is $O(nd^3)$ and cannot.

(b) MRV picks the next variable: fewest remaining values, because all variables must be assigned anyway, so ordering is free — and small branching factors near the root plus immediate detection of empty domains shrink the tree.

(c) LCV picks the next value: the one deleting least from neighbours, because only one solution is needed and the first value tried should be the most promising.

Technique: knowing what each piece of CSP machinery is for, not just what it does. Read: Chapter 4 — Constraint Satisfaction, the filtering and ordering sections.

2.5  CSP: air traffic control

Problem 2.5Schedule five planes onto two runways and four time slots

Five planes A, B, C, D, E. Two runways, international and domestic. Four time slots 1, 2, 3, 4 on each runway. Each plane needs one (runway, slot) reservation to land or take off. Constraints:

  • B has lost an engine and must land in slot 1.
  • D cannot arrive before slot 3, so its slot is $\ge 3$.
  • A is low on fuel and must be handled by slot 2 at the latest.
  • D must land before C takes off (passengers transfer from D to C).
  • No two aircraft may hold the same slot on the same runway.

(a) Formulate as a CSP: variables, domains, and constraints — constraints written in mathematical notation, not words.

Now add two more facts: A, B, C are international flights and can only use the international runway; D and E are domestic and can only use the domestic runway.

(b) Give the new domain and draw the constraint graph. (c) Run AC-3 (unary constraints first) and give the resulting domains. (d) Instead, use MRV with forward checking and list the (variable, value) pairs in the order they are tried, including ones later undone. Break ties by lower letter and lower value.

Step 1 — What is actually being asked?

Four separate skills, which is why this is the most exam-like problem in the recitations:

  1. (a) Formulation, with the specific demand that constraints be symbolic. "No two planes share a slot" earns fewer marks than $\text{slot}(X) \neq \text{slot}(Y)$.
  2. (b) Recognising that a change in the constraints can shrink the domain, because information moved from the value into the variable's identity.
  3. (c) AC-3 by hand, to a fixpoint.
  4. (d) Backtracking with MRV + forward checking, with the undone assignments shown — they are the marks.

A trap in (c)/(d): arc consistency and backtracking are different procedures and part (d) explicitly says to start from the unary-filtered domains, not from the AC-3 output of part (c). If you carry (c)'s domains into (d) you will get a shorter trace and lose the marks for the backtrack.

Step 2 — (a) The first formulation

Variables: one per plane — $A, B, C, D, E$. (Not one per slot. Choosing variables = planes is what makes the "at most one reservation each" requirement automatic, since a variable holds exactly one value.)

Domains: each variable takes a pair

$D_X = \{\text{intl}, \text{dom}\} \times \{1,2,3,4\}$,   so $|D_X| = 8$.

Write $X[0]$ for the runway component and $X[1]$ for the slot component of the pair assigned to $X$.

Constraints. Unary:

$B[1] = 1 \qquad D[1] \ge 3 \qquad A[1] \le 2$

Binary:

$D[1] < C[1]$

$X \neq Y \quad \text{for all pairs } X \neq Y \in \{A,B,C,D,E\}$

where the last line compares the whole pairs — two planes may share a slot if they are on different runways, and may share a runway if they are in different slots, but not both. It is an all-different constraint over 5 variables, which decomposes into $\binom{5}{2} = 10$ binary constraints.

Common mistake

Writing the no-collision constraint as $X[1] \neq Y[1]$ (slots differ). That is too strong — it forbids two planes from using the same slot on different runways, which the problem explicitly allows, and with 5 planes and 4 slots it would make the CSP unsatisfiable. Also note that writing "$A \neq B \neq C \neq D \neq E$" as a chain is sloppy notation for the all-different constraint; it literally only says consecutive ones differ. Say "pairwise distinct" or give the 10 constraints.

Step 3 — (b) The runway constraints collapse the domain

Now A, B, C are forced onto the international runway and D, E onto the domestic one. The runway component of every variable's value is therefore determined by which variable it is, so carrying it inside the value is redundant. Drop it:

Variables: $A, B, C, D, E$.    Domain: $\{1, 2, 3, 4\}$ for every variable.

This is worth pausing on, because it is a general modelling move: information that is constant per variable belongs in the variable, not in the domain. The domain shrank from 8 values to 4, which halves the branching factor at every node of the search tree.

The constraints change too. The slot-collision constraint now applies only within a runway:

  • International runway: $A \neq B$, $A \neq C$, $B \neq C$ — a triangle.
  • Domestic runway: $D \neq E$ — a single edge.
  • Cross-runway: $D < C$ survives, because it is about time, not about runway occupancy. This is the only edge joining the two groups.
  • Unary, unchanged: $B = 1$, $D \ge 3$, $A \le 2$.

Note what vanished: there is no longer any constraint between A and D, or between B and E, and so on — planes on different runways cannot collide. Six of the original ten binary constraints disappear.

What to notice: the graph is almost two components, joined by the single edge C–D. That one edge is the whole difficulty of the problem — without it, the international triangle and the domestic edge could be solved independently in seconds. It is also why AC-3's propagation in part (c) travels so far: a deletion in C's domain reaches E, three arcs away, through C–D and D–E.

Unary constraints first. These are not arcs; just apply them directly.

Common mistake

Stopping after one pass. In this problem the deletion at step 4 is only possible because steps 1–3 already happened, and step 6 is only possible because of step 5. Forward checking after an assignment to B would have done step 1 and step 2 and stopped, leaving $D_C = \{2,3,4\}$ and $D_D = \{3,4\}$. The chain is the point of AC-3. Also: this is not the same as having solved the CSP — arc consistency is necessary, not sufficient, and $D_E$ still has three values.

(a) Variables = planes; domain = $\{\text{intl},\text{dom}\} \times \{1,2,3,4\}$; unary $B[1]=1$, $D[1]\ge3$, $A[1]\le2$; binary $D[1] < C[1]$ and all 10 pairs $X \neq Y$ on whole (runway, slot) pairs.

(b) Domain collapses to $\{1,2,3,4\}$; graph = triangle A-B-C, edge D-E, single bridge C-D carrying $D < C$.

(c) $A\{2\}$, $B\{1\}$, $C\{4\}$, $D\{3\}$, $E\{1,2,4\}$ — which exactly brackets the 3 solutions.

(d) (B,1), (A,2), (C,3), (C,4), (D,3), (E,1) — one backtrack, at C.

Takeaway. Compare (c) and (d) directly. AC-3 pinned four variables and cost one propagation pass with no search at all; MRV + forward checking searched and hit a dead end, because forward checking from $C = 3$ could see D's domain emptying but could never have predicted it in advance. That is the trade the chapter is about: filtering harder means searching less, and which side is cheaper depends on the instance.

Next variable. Johnny 2, Isha 1. Maximum remaining values picks Johnny — which is already the mistake: Isha is down to a single option and we are not committing to it.

Value for Johnny via most constraining: $J = $ Yellow leaves Isha $\{$P$\}$ (1); $J = $ Pink leaves Isha $\{\,\}$ (0). Smallest total wins, so Johnny = Pink.

Isha now has an empty domain. Dead end — backtrack. Retract Johnny = Pink and try Johnny = Yellow. Isha $\{$P$\}$ → Isha = Pink. Complete.

Amy = Red,   Johnny = Yellow,   Isha = Pink   —   1 backtrack

And notice how specifically wrong the second heuristic pair was: the "most constraining value" rule deliberately chose the value that emptied Isha's domain. It did not stumble into failure; it optimised for it.

Answer & the takeaway

(a) 0 backtracks. (b) 1 backtrack.

One backtrack on a three-variable problem does not sound dramatic, and that is worth saying honestly. The point is the mechanism, which scales:

  • MRV assigns the tightest variable first, so a contradiction surfaces at shallow depth. Reversing it leaves the tight variable unassigned while you make choices that can destroy it — which is exactly what happened to Isha.
  • LCV tries the value most likely to leave a solution reachable. Reversing it means deliberately picking the value most likely to kill one, and on this instance it picked precisely the fatal one.

On a problem with $n$ variables, a dead end discovered at depth $k$ costs you the whole subtree below it. MRV pushes $k$ down; its mirror pushes $k$ up. The factor is exponential in $n-k$, so one backtrack here is the visible tip of a real effect.

Common mistake

Mixing the directions — "most constrained variable, most constraining value". That sounds symmetric and is wrong, because, as Problem 2.4 explains, variables must all be assigned (so seek failure early) while only one value per variable survives (so seek success early). Correct pairing: most constrained variable, least constraining value.

Technique: applying MRV and LCV in the right directions and counting backtracks. Read: Chapter 4, the ordering-heuristics section.

3.1  Definitions batch: trees, entropy, conditional entropy, mutual information

Problem 3.1Four definitions, stated precisely and sanity-checked

Define, with formulas: (a) a decision tree, (b) entropy, (c) conditional entropy, (d) mutual information.

For each, also say what the quantity is measured in and what its extreme values mean. That is where partial credit lives.

Step 1 — What is actually being asked?

These four are not independent: (d) is built from (b) and (c), and (a) is the thing the other three are used to build. So the right way to hold them is as a chain — entropy measures disorder; conditional entropy measures the disorder left after you look at a feature; mutual information is the difference, i.e. how much looking helped; and a decision tree is what you get by repeatedly choosing the feature that helps most.

A definition answer that states the formula and nothing else is fragile. State the formula, name every symbol, and give the two extremes.

Step 2 — (a) Decision tree
Definition

A decision tree is a classifier (or regressor) shaped as a rooted tree in which

  • each internal node tests one attribute of the input,
  • each branch out of that node corresponds to one outcome of the test,
  • each leaf carries a predicted label.

Prediction: start at the root, follow the branch matching the input's value for the tested attribute, repeat, and output the label at the leaf you reach.

Small worked example — "will it rain today?":

            Cloudy?
           /        \
         no          yes
         |            |
        NO       Temperature
                  /        \
              < 30F       ≥ 30F
                |            |
               YES           NO

Two things to say out loud about this structure, because they come back in part 3.4: each test looks at a single attribute, and the branches out of a node partition the data reaching it. Together those two facts mean a decision tree's decision regions are built from axis-aligned cuts — it can never draw a diagonal boundary in one test.

Step 3 — (b) Entropy
Definition

The entropy of a discrete random variable $Y$ is $$H(Y) = -\sum_{y} P(Y = y) \log_2 P(Y = y).$$

The sum runs over every value $y$ that $Y$ can take. Using $\log_2$ makes the unit the bit. The convention $0 \log_2 0 = 0$ is used, justified by $\lim_{p \to 0^+} p \log_2 p = 0$.

What it means: the average number of bits needed to communicate a draw of $Y$ under an optimal code; equivalently, how uncertain you are about the outcome. High entropy = less confident.

Extremes, for $Y$ over $k$ values: minimum $H(Y) = 0$ exactly when $Y$ is deterministic (one outcome has probability 1); maximum $H(Y) = \log_2 k$ exactly when $Y$ is uniform. For a binary $Y$ those are 0 and 1 bit.

Step 4 — (c) Conditional entropy
Definition

The conditional entropy of $Y$ given $X$ is the expected entropy of $Y$ once you know $X$, averaged over $X$'s distribution: $$H(Y \mid X) = \sum_{x} P(X = x)\, H(Y \mid X = x)$$ where $H(Y \mid X = x) = -\sum_y P(Y=y \mid X=x) \log_2 P(Y = y \mid X = x)$.

The outer sum is over values of $X$; the inner one over values of $Y$.

Practically, for a dataset: split the rows into groups by their value of $X$, compute the label entropy within each group, and average those numbers weighted by group size.

Common mistake

Averaging the per-group entropies unweighted. A group of 1 row and a group of 7 rows do not count equally; the weights are $P(X=x) = (\text{group size}) / N$. This is the single most common arithmetic slip in decision-tree questions, and it survives undetected because the answer still looks like a plausible number.

Step 5 — (d) Mutual information — and a typo to watch for
Definition

The mutual information between $Y$ and $X$ (also called information gain when used to pick a split) is $$I(Y; X) = H(Y) - H(Y \mid X).$$ It is the reduction in uncertainty about $Y$ from observing $X$.

Watch the handout here

The recitation's definitions page writes this as $I(Y;X) = H(Y) - H(Y \mid X = x)$, with a specific value $x$ on the right. That is a typo. $H(Y \mid X = x)$ is a number attached to one value of $X$, so the right-hand side would depend on $x$ while the left-hand side does not — and it can even come out negative, since observing a particular $x$ can leave you more uncertain than you started. Mutual information uses $H(Y \mid X)$, the expectation over all $x$, and it is always $\ge 0$. Every computation in the same handout correctly uses $H(Y \mid X)$; only the definition line is wrong.

Properties worth being able to state:

  • Non-negative: $I(Y;X) \ge 0$ always. Information cannot hurt on average.
  • Symmetric: $I(Y;X) = I(X;Y)$, which is why it is called mutual.
  • Bounded: $I(Y;X) \le H(Y)$, with equality when $X$ determines $Y$ — a perfect split.
  • Zero iff independent: see 3.2(4) below.

Why trees use it: $H(Y)$ is fixed for the data at a node, so maximising $I(Y; X_j)$ over candidate features $j$ is the same as minimising $H(Y \mid X_j)$. That is the shortcut worth using under time pressure: you can skip computing $H(Y)$ entirely and just pick the feature with the smallest weighted post-split entropy.

3.2  Entropy and mutual information: quick computations

Problem 3.2Four one-liners
  1. Entropy of a fair coin toss.
  2. Entropy of a coin that always lands tails. (Use $0 \log_2 0 = 0$.)
  3. Entropy of a fair six-sided die roll.
  4. When is $I(Y;X) = 0$?
Step 1 — What is actually being asked?

Items 1–3 are calibration: they establish the three reference points you should be able to recall instantly, so that in a longer problem you can tell whether an entropy you just computed is plausible. Item 4 is conceptual.

Reference points to memorise: uniform over $k$ outcomes gives $\log_2 k$; deterministic gives 0; and for a binary variable the whole range is $[0, 1]$.

Step 2 — (1) and (2): the two extremes

Fair coin. $P(H) = P(T) = \tfrac12$:

$H(Y) = -\tfrac12 \log_2 \tfrac12 - \tfrac12 \log_2 \tfrac12 = -\tfrac12(-1) - \tfrac12(-1) = \mathbf{1} \text{ bit}$

Maximum possible for a binary variable, and it is the definition of the unit: one bit is exactly the uncertainty in one fair coin.

Always-tails coin. $P(H) = 0$, $P(T) = 1$:

$H(Y) = -0\log_2 0 - 1 \log_2 1 = -0 - 0 = \mathbf{0} \text{ bits}$

Both terms vanish, for different reasons: the first by the $0\log_2 0 = 0$ convention, the second because $\log_2 1 = 0$. Zero uncertainty, so no bits are needed to tell you the outcome — you already know it.

Step 3 — (3) Fair die

Six equally likely outcomes, each with probability $\tfrac16$:

$\displaystyle H(Y) = -\sum_{i=1}^{6} \tfrac16 \log_2 \tfrac16 = -6 \cdot \tfrac16 \log_2 \tfrac16 = -\log_2 \tfrac16 = \log_2 6 \approx \mathbf{2.585} \text{ bits}$

Leave it as $\log_2 6$ unless a decimal is asked for. A useful sanity check: $2 < 2.585 < 3$, matching the fact that 6 outcomes need more than 2 but fewer than 3 bits ($2^2 = 4 < 6 < 8 = 2^3$). This is also the general result — uniform over $k$ gives $\log_2 k$, which is the maximum entropy for a variable with $k$ outcomes.

Step 4 — (4) When is mutual information zero?

Exactly when $X$ and $Y$ are independent.

From the definition, $I(Y;X) = 0$ means

$H(Y) - H(Y \mid X) = 0 \quad \Longleftrightarrow \quad H(Y) = H(Y \mid X).$

In words: knowing $X$ leaves your uncertainty about $Y$ completely unchanged. That is what independence is, informationally. (Formally $I(Y;X) = 0 \iff P(X,Y) = P(X)P(Y)$, and the "only if" direction relies on $I \ge 0$ with equality only in that case.)

Three consequences worth having ready:

  • In tree-building: a feature with $I(Y; X_j) = 0$ is useless at this node — splitting on it leaves every child with the same label distribution as the parent. If every feature has zero mutual information, no split helps and you should stop and make a leaf.
  • $I \ge 0$ always, so zero is the floor, not a mid-range value. There is no such thing as a feature that hurts you on average.
  • But a single value can hurt. $H(Y \mid X = x) > H(Y)$ is possible for a particular $x$ — observing one specific outcome can leave you more confused. It is only the average over $x$ that is guaranteed not to. This is exactly why the definition typo in 3.1(d) matters.

Technique: entropy arithmetic and the independence characterisation of mutual information. Read: Chapter 7.

Problem 3.4What could a decision tree's boundary look like on these two datasets?

Two 2-feature, 2-class datasets, both drawn in Figure 9. For each, describe a decision tree achieving zero training error and sketch its boundary.

Dataset A — classes by quadrant. Dataset B — classes separated by the line $x_2 = x_1 + 0.6$.

Step 1 — What is actually being asked?

This is a question about the hypothesis class, not about any particular algorithm. One fact decides everything:

The one fact

Every internal node tests one feature, so every cut is a hyperplane perpendicular to a feature axis — "$x_1 < t$" or "$x_2 < t$". A decision tree's decision regions are therefore axis-aligned boxes, always, no matter how deep it is.

So the question becomes: can this dataset be carved up by axis-aligned boxes, and how many do you need? "Zero error" is always achievable if no two identical points carry different labels — worst case you isolate each point in its own box. The real question is how many cuts, and that is what distinguishes the two datasets.

Step 2 — Dataset A: two cuts suffice

The classes sit in diagonal quadrants: circles in bottom-left and top-right, crosses in bottom-right and top-left. That is an XOR pattern, and it is exactly what axis-aligned cuts are good at — even though a single straight line cannot do it at all.

3.5  Max depth: the notebook discussion questions

Problem 3.5Five questions about tuning tree depth on the Iris dataset

The recitation's notebook sweeps max_depth for a decision tree on Iris (4 features, 3 classes, 150 examples) and plots training and validation error.

  1. What is the best value of max_depth, and why?
  2. Why is the error large when max_depth is very small?
  3. How is max_depth related to overfitting?
  4. Why can't we draw the decision boundaries the way lecture did?
  5. For which values of max_depth are the boundaries most complex?

These are the only questions on this page whose answer depends on a specific random split, so item 1's answer is a range, not a number.

Step 1 — What is actually being asked?

All five are the bias–variance story told through one hyperparameter. The frame that answers all of them at once:

max_depth is a capacity knob. Turning it up lets the tree carve the feature space into more and smaller boxes. Too few boxes and the tree cannot express the pattern (underfitting, high bias). Too many and each box is shaped by a handful of points, including their noise (overfitting, high variance). Training error falls monotonically as depth rises; validation error falls, bottoms out, then rises. You tune on validation error, never on training error.

Step 2 — (1) and (2): the small-depth end

(1) Best max_depth: somewhere around 2 to 8, varying with the train/validation split and the implementation. The criterion is the one that matters: the depth minimising validation error, not training error, which keeps improving all the way down and so can never select a depth.

Iris being nearly separable on two of its four features, depth 2–3 already does well, and anything deeper buys very little. When several depths tie on validation error, prefer the shallowest — fewer parameters, better expected generalisation, and easier to explain.

(2) Why the error is large at very small depth: with max_depth $= 1$ the tree makes a single split, so it has exactly 2 leaves and can output at most 2 distinct labels. On a 3-class problem, one class is therefore guaranteed to be wrong — a structural ceiling, independent of data or tuning. More generally, a shallow tree's leaves each hold a large and mixed set of rows; the leaf predicts the majority and is wrong on the rest. The leaf's label entropy is still high, which is exactly the diagnostic: a leaf with high entropy is a leaf that should have been split. This is underfitting: insufficient capacity to represent the structure that is really there.

Note that the depth-1 argument is a nice crisp thing to write in an exam: depth $d$ gives at most $2^d$ leaves, hence at most $2^d$ distinct predictions, so with $K$ classes you need $d \ge \log_2 K$ before zero error is even possible.

Step 3 — (3) and (5): the large-depth end

(3) Relation to overfitting. Deeper trees overfit. The mechanism, concretely: as depth grows, the algorithm keeps splitting until leaves contain one or two training points, and it will happily split on a feature that separates two points by accident. That split is memorisation, not pattern. Result: training error → 0 while validation error rises, because the fine structure was noise and the noise does not repeat in new data.

The honest refinement: depth is a bound on capacity, not capacity itself. If the data is cleanly separable with few splits, the tree may stop early regardless of a large max_depth, and raising the cap further changes nothing. That is why the validation curve usually flattens at the right rather than shooting up — and why the answer to (1) is a range.

(5) Most complex boundaries. At the largest depths. Each additional level adds more axis-aligned cuts, so the decision regions become more numerous and smaller and the boundary becomes a finer staircase — precisely the shape in Figure 9's right panel, with more and smaller steps. Maximum depth gives maximum boundary complexity, and past the validation minimum that extra complexity is tracking noise.

A sharper version of the same claim: boundary complexity is governed by the number of leaves, which is at most $2^d$. Depth bounds complexity exponentially, which is why a modest change in max_depth can change the picture so much.

Step 4 — (4) Why you cannot draw the boundary

Because Iris has 4 features (sepal length, sepal width, petal length, petal width), so its feature space is $\mathbb{R}^4$ and the decision boundary is a 3-dimensional surface in it. A sheet of paper shows 2 dimensions.

Lecture's pictures were drawn after picking 2 of the 4 features and discarding the rest, which makes the plot honest about that 2-feature model and misleading about the 4-feature one.

The standard workarounds, worth naming:

  • Select 2 features and train on only those. Honest, but a different model.
  • Project to 2 dimensions (PCA, say) and plot. Shows the data, but the boundary becomes approximate, since a projected boundary is not generally a boundary.
  • Plot a 2-D slice: vary two features and hold the other two at their means. Exact, but only along that slice.
  • Draw the tree itself instead of the boundary. For a tree this is the best option: the tree is a complete, exact and readable description of the boundary in any number of dimensions, which is not true of most model classes.

Technique: hyperparameter tuning as capacity control; reading a train/validation error curve; the limits of visualisation above 2 features. Read: Chapter 12 — Regularization & cross-validation for the tuning procedure, and Chapter 6 for depth as a capacity bound.

Recitation 4 — vector and matrix derivatives

Four problems, and they are the mechanics students lose the most marks on — not because the ideas are hard but because the bookkeeping is unforgiving. Every line is shown below. The habit to build: check the shape of every expression before and after every step. A shape mismatch is a mistake, every time, with no exceptions.

4.1  Definitions batch: partial, gradient, Jacobian, layout

Problem 4.1Four definitions, each with its shape

Define, with a worked example: (a) partial derivative, (b) vector derivative (gradient), (c) matrix derivative (Jacobian), (d) numerator versus denominator layout.

Use $f(x_1, x_2) = x_1^3 + e^{x_2} x_1$ throughout for (a) and (b).

Step 1 — What is actually being asked?

One idea, four packagings, distinguished entirely by what is a scalar and what is a vector on each side:

FunctionDerivative objectShape
partial$f: \mathbb{R}^M \to \mathbb{R}$one number per input slotscalar
gradient$f: \mathbb{R}^M \to \mathbb{R}$all the partials stacked$M \times 1$
Jacobian$\mathbf{f}: \mathbb{R}^M \to \mathbb{R}^N$every output's partial w.r.t. every input$M \times N$ or $N \times M$

That last ambiguity is precisely what (d) is about, and it is the reason this course states a layout convention on every question that needs one.

Step 2 — (a) Partial derivative
Definition

For a multivariable function, the partial derivative with respect to one input is the ordinary derivative taken while holding every other input constant. Written $\dfrac{\partial f}{\partial x_i}$.

With $f(x_1, x_2) = x_1^3 + e^{x_2} x_1$:

$\dfrac{\partial f}{\partial x_1} = \dfrac{\partial}{\partial x_1}\!\left(x_1^3\right) + \dfrac{\partial}{\partial x_1}\!\left(e^{x_2} x_1\right) = 3x_1^2 + e^{x_2}$

In the second term, $e^{x_2}$ is a constant multiplier as far as $x_1$ is concerned, so it comes along untouched. And the other partial:

$\dfrac{\partial f}{\partial x_2} = 0 + x_1 e^{x_2} = x_1 e^{x_2}$

Here $x_1^3$ has no $x_2$ in it, so it differentiates to 0, and $x_1$ is the constant multiplier.

Step 3 — (b) Vector derivative / gradient
Definition

For $f: \mathbb{R}^M \to \mathbb{R}$, the gradient collects the partials into a column vector whose $i$-th entry is $\partial f / \partial x_i$: $$\nabla f(\mathbf{x}) = \frac{\partial f}{\partial \mathbf{x}} = \begin{bmatrix} \partial f/\partial x_1 \\ \vdots \\ \partial f / \partial x_M\end{bmatrix} \in \mathbb{R}^{M \times 1}.$$

For our $f$, with $M = 2$:

$\nabla f(\mathbf{x}) = \begin{bmatrix} 3x_1^2 + e^{x_2} \\ x_1 e^{x_2} \end{bmatrix}$

Notation note the handout flags, and it matters: the $\mathbf{x}$ in $\nabla f(\mathbf{x})$ is bold — a vector, not a scalar. Throughout this course bold lowercase means a vector, capital means a matrix, and plain lowercase means a scalar. Getting that wrong turns a correct derivation into an incoherent one, and it is the first thing a grader checks.

Step 4 — (c) Matrix derivative / Jacobian
Definition

For a vector-valued function $\mathbf{y} = \mathbf{f}(\mathbf{x})$ with $\mathbf{f}: \mathbb{R}^M \to \mathbb{R}^N$, the derivative $\partial \mathbf{y} / \partial \mathbf{x}$ is a matrix holding every output's partial with respect to every input. In denominator layout (rows indexed by the input):

$$\frac{\partial \mathbf{y}}{\partial \mathbf{x}} = \begin{bmatrix} \frac{\partial y_1}{\partial x_1} & \frac{\partial y_2}{\partial x_1} & \cdots & \frac{\partial y_N}{\partial x_1} \\ \frac{\partial y_1}{\partial x_2} & \frac{\partial y_2}{\partial x_2} & \cdots & \frac{\partial y_N}{\partial x_2} \\ \vdots & & \ddots & \vdots \\ \frac{\partial y_1}{\partial x_M} & \frac{\partial y_2}{\partial x_M} & \cdots & \frac{\partial y_N}{\partial x_M}\end{bmatrix} \in \mathbb{R}^{M \times N}$$

The gradient is the special case $N = 1$: a single column. The numerator layout is this matrix transposed, $N \times M$ — see Step 5.

Step 5 — (d) Numerator vs denominator layout, and how to never confuse them

The two layouts contain identical information and differ by a transpose. The course states which one to use; you must be able to work in either.

The rule that settles it in one second

The layout is named after whatever supplies the number of ROWS. Numerator layout ⇒ rows $=$ size of the numerator (the thing being differentiated). Denominator layout ⇒ rows $=$ size of the denominator (the thing you differentiate by).

Applying it, with $\mathbf{y} \in \mathbb{R}^N$, $\mathbf{v} \in \mathbb{R}^{N \times 1}$, $A \in \mathbb{R}^{M \times N}$, $y$ a scalar:

ExpressionNumerator layoutDenominator layout
$\dfrac{\partial y}{\partial \mathbf{x}}$  (scalar by vector)row vector, $1 \times M$column vector, $M \times 1$
$\dfrac{\partial \mathbf{y}}{\partial x}$  (vector by scalar)column vector, $N \times 1$row vector, $1 \times N$
$\dfrac{\partial\, \mathbf{u}^\top \mathbf{v}}{\partial \mathbf{v}}$$\mathbf{u}^\top$$\mathbf{u}$
$\dfrac{\partial\, A\mathbf{v}}{\partial \mathbf{v}}$$A$$A^\top$

Check the last row with the rule. $A\mathbf{v} \in \mathbb{R}^{M}$ is the numerator, $\mathbf{v} \in \mathbb{R}^{N}$ the denominator. Numerator layout wants $M$ rows, and $A$ is $M \times N$ — correct. Denominator layout wants $N$ rows, and $A^\top$ is $N \times M$ — correct. The rule never needs memorising past that.

Super important, and it is not a platitude

Check that the shapes match on both sides of every equality you write. This is not a tidiness tip — in this material a shape mismatch is a proof that something is wrong, and it is the only error-detection tool you have in an exam with no computer. Problem 4.3 is built entirely around one such mismatch.

Technique: derivative shapes and layout conventions. Read: Chapter 8 — Linear regression, which sets up this notation, and Chapter 9, which uses it.

4.2  Deriving vector derivatives

Problem 4.2Gradient of a squared distance

Let $J(\mathbf{z}) = \lVert \mathbf{y} - \mathbf{z}\rVert_2^2$ with $\mathbf{y} = \begin{bmatrix} y_1 \\ y_2\end{bmatrix}$ and $\mathbf{z} = \begin{bmatrix} z_1 \\ z_2 \end{bmatrix}$. Find $\nabla J(\mathbf{z})$.

Step 1 — What is actually being asked?

Do not reach for an identity. The whole point of this problem is the technique you fall back on when you do not recognise the expression: expand to scalars, differentiate component by component, then re-stack into a vector. That technique always works and it is what the proof in 4.4 does at larger scale.

Shape check before starting: $J$ is a scalar function of a $2 \times 1$ vector, so $\nabla J(\mathbf{z})$ must be $2 \times 1$.

Step 2 — Expand the norm into scalars

By definition $\lVert \mathbf{a} \rVert_2^2 = \sum_i a_i^2$, so with $\mathbf{a} = \mathbf{y} - \mathbf{z}$:

$J(\mathbf{z}) = \left\lVert \begin{bmatrix} y_1 - z_1 \\ y_2 - z_2\end{bmatrix} \right\rVert_2^2 = (y_1 - z_1)^2 + (y_2 - z_2)^2$

Now it is an ordinary two-variable calculus problem with no vectors in sight. Note the squared norm has no square root, which is exactly why this is pleasant to differentiate — squared loss is used partly for this reason.

Step 3 — Differentiate each component

With respect to $z_1$, the second term is constant:

$\dfrac{\partial J}{\partial z_1} = \dfrac{\partial}{\partial z_1}(y_1 - z_1)^2 = 2(y_1 - z_1) \cdot \dfrac{\partial (y_1 - z_1)}{\partial z_1} = 2(y_1 - z_1)(-1) = -2(y_1 - z_1)$

The chain rule supplies the inner derivative $-1$, and that minus sign is the single most commonly dropped thing in this problem. Identically for $z_2$:

$\dfrac{\partial J}{\partial z_2} = -2(y_2 - z_2)$

Answer & the takeaway

Stack the partials into a column:

$\nabla J(\mathbf{z}) = \begin{bmatrix} -2(y_1 - z_1) \\ -2(y_2 - z_2)\end{bmatrix} = -2\begin{bmatrix} y_1 - z_1 \\ y_2 - z_2 \end{bmatrix} = \boxed{-2(\mathbf{y} - \mathbf{z})}$

Shape check: $\mathbf{y} - \mathbf{z}$ is $2 \times 1$, scaled by $-2$, still $2 \times 1$. Matches the requirement from Step 1. ✓

Verification: a central-difference numerical gradient of $J$ at $\mathbf{y} = (2, -1)$, $\mathbf{z} = (0.5, 0.4)$ gives $(-3.0,\ 2.8)$, and $-2(\mathbf{y} - \mathbf{z}) = -2(1.5,\ -1.4) = (-3.0,\ 2.8)$. Agreed to 6 decimal places.

Takeaways. The result generalises immediately to any dimension: $\nabla_{\mathbf{z}} \lVert \mathbf{y} - \mathbf{z}\rVert_2^2 = -2(\mathbf{y} - \mathbf{z})$. Two things to carry:

  • It points away from $\mathbf{y}$. The negative gradient is $+2(\mathbf{y} - \mathbf{z})$, which points from $\mathbf{z}$ straight at $\mathbf{y}$. So gradient descent on squared distance walks you directly towards the target — a useful geometric check on any gradient you derive.
  • Setting it to zero gives $\mathbf{z} = \mathbf{y}$, the unique minimiser, which is obviously right and confirms no sign error.

Technique: expand-differentiate-restack, plus the chain-rule sign. This is exactly the gradient of the squared-error loss in Chapter 8, where $\mathbf{z} = X\boldsymbol{\theta}$.

Problem 4.2bJacobian of elementwise squaring — the shape trap

A function squares each element of $\mathbf{x} \in \mathbb{R}^{3 \times 1}$:

$\mathbf{y} = f(\mathbf{x}) = f\!\left(\begin{bmatrix} x_1 \\ x_2 \\ x_3\end{bmatrix}\right) = \begin{bmatrix} x_1^2 \\ x_2^2 \\ x_3^2 \end{bmatrix}$

What is $\dfrac{\partial \mathbf{y}}{\partial \mathbf{x}}$? Use numerator layout.

Step 1 — The wrong answer, and why it is wrong

The tempting answer is $\dfrac{\partial \mathbf{y}}{\partial \mathbf{x}} = 2\mathbf{x}$, by analogy with the scalar fact $\frac{d}{dx} x^2 = 2x$.

Shape check kills it instantly. This is a map $\mathbb{R}^3 \to \mathbb{R}^3$, so its derivative is a Jacobian: $3 \times 3$ in either layout. But $2\mathbf{x}$ is $3 \times 1$. Nine numbers are required and three were offered, so the answer cannot be right — no calculus needed to know that.

This is the payoff of the shape habit. You caught a wrong answer without differentiating anything.

Step 2 — Build the Jacobian entry by entry

Numerator layout: rows indexed by the numerator $\mathbf{y}$, columns by the denominator $\mathbf{x}$. So entry $(i,j)$ is $\partial y_i / \partial x_j$:

$\dfrac{\partial \mathbf{y}}{\partial \mathbf{x}} = \begin{bmatrix} \frac{\partial y_1}{\partial x_1} & \frac{\partial y_1}{\partial x_2} & \frac{\partial y_1}{\partial x_3} \\[2pt] \frac{\partial y_2}{\partial x_1} & \frac{\partial y_2}{\partial x_2} & \frac{\partial y_2}{\partial x_3} \\[2pt] \frac{\partial y_3}{\partial x_1} & \frac{\partial y_3}{\partial x_2} & \frac{\partial y_3}{\partial x_3}\end{bmatrix}$

Now evaluate. Since $y_i = x_i^2$ depends on $x_i$ only:

  • On the diagonal: $\partial y_i / \partial x_i = 2x_i$.
  • Off the diagonal: $\partial y_i / \partial x_j = 0$ for $i \neq j$, because $y_i$ contains no $x_j$ at all.

$\dfrac{\partial \mathbf{y}}{\partial \mathbf{x}} = \begin{bmatrix} 2x_1 & 0 & 0 \\ 0 & 2x_2 & 0 \\ 0 & 0 & 2x_3\end{bmatrix} = 2\,\mathrm{diag}(\mathbf{x})$

Answer & the takeaway

$\boxed{\dfrac{\partial \mathbf{y}}{\partial \mathbf{x}} = 2\,\mathrm{diag}(x_1, x_2, x_3) \in \mathbb{R}^{3\times3}}$

In this case the two layouts agree, because the matrix is symmetric (diagonal). That is a coincidence of this problem, not a general fact — do not let it make you careless about layout elsewhere.

Takeaways.

  • Diagonal Jacobian $\iff$ elementwise function. The zero off-diagonal entries are the statement "output $i$ depends only on input $i$". Whenever you see an elementwise operation, expect a diagonal Jacobian, and vice versa. This is why elementwise activation functions are cheap to backpropagate through — a diagonal matrix product is just a vectorised multiply.
  • "$2\mathbf{x}$" was not merely the wrong shape, it was the wrong kind of object. The scalar intuition does not transfer; what transfers is the entry-by-entry construction.
  • Shape-check first. It is faster than differentiating and it catches the most common class of error.

Technique: Jacobian construction and layout discipline. Read: Chapter 9 — Optimization.

4.3  How about a proof?  $\dfrac{\partial}{\partial \mathbf{v}} \mathbf{v}^\top A \mathbf{v} = (A^\top + A)\mathbf{v}$

Problem 4.3Prove the quadratic-form derivative, in denominator layout

Assuming denominator layout, prove

$\dfrac{\partial}{\partial \mathbf{v}} \mathbf{v}^\top A \mathbf{v} = (A^\top + A)\mathbf{v}$

for $\mathbf{v} \in \mathbb{R}^2$ and $A \in \mathbb{R}^{2 \times 2}$. Then extend to general dimension.

Suggested route: expand $A\mathbf{v}$, then $\mathbf{v}^\top A \mathbf{v}$; write the scalar partials; and expand the right-hand side too, so you can see where you are heading.

Step 1 — What is actually being asked, and the strategy

A proof by direct computation. The strategy that makes it painless is the hint's third line: work from both ends. Expand the left side down to scalars; expand the right side down to scalars; show they are the same two expressions. Marching blindly from the left and hoping to recognise the answer is how people get stuck.

Shape check first. $\mathbf{v}^\top A \mathbf{v}$ is $(1\times2)(2\times2)(2\times1) = 1 \times 1$ — a scalar. Differentiating a scalar by a $2\times1$ vector in denominator layout gives a $2 \times 1$ column. On the right, $(A^\top + A)$ is $2\times2$ and $\mathbf{v}$ is $2 \times 1$, so the product is $2 \times 1$. ✓ Both sides are columns of length 2, so the claim is at least coherent.

Step 2 — Expand the left side to a scalar polynomial

Write everything out:

$\mathbf{v} = \begin{bmatrix} v_1 \\ v_2\end{bmatrix}, \qquad A = \begin{bmatrix} A_{11} & A_{12} \\ A_{21} & A_{22}\end{bmatrix}, \qquad A^\top = \begin{bmatrix} A_{11} & A_{21} \\ A_{12} & A_{22}\end{bmatrix}$

First $\mathbf{v}^\top A$, a $1 \times 2$ row:

$\mathbf{v}^\top A = \begin{bmatrix} v_1 & v_2\end{bmatrix}\begin{bmatrix} A_{11} & A_{12} \\ A_{21} & A_{22}\end{bmatrix} = \begin{bmatrix} A_{11}v_1 + A_{21}v_2 & \;\; A_{12}v_1 + A_{22}v_2\end{bmatrix}$

Then multiply by $\mathbf{v}$ on the right:

$\mathbf{v}^\top A \mathbf{v} = \begin{bmatrix} A_{11}v_1 + A_{21}v_2 & A_{12}v_1 + A_{22}v_2\end{bmatrix}\begin{bmatrix} v_1 \\ v_2\end{bmatrix}$

$= A_{11}v_1^2 + A_{21}v_1 v_2 + A_{12}v_1v_2 + A_{22}v_2^2$

A scalar quadratic in $v_1, v_2$. Note that $A_{12}$ and $A_{21}$ appear only through the cross term, and only as the sum $A_{12} + A_{21}$. That observation is already the whole content of the theorem; the rest is bookkeeping.

Step 3 — Take the two scalar partials

Differentiate the polynomial with respect to $v_1$, treating $v_2$ as constant. The $A_{22}v_2^2$ term vanishes:

$\dfrac{\partial}{\partial v_1}\left(\mathbf{v}^\top A \mathbf{v}\right) = 2A_{11}v_1 + A_{21}v_2 + A_{12}v_2$

And with respect to $v_2$; now $A_{11}v_1^2$ vanishes:

$\dfrac{\partial}{\partial v_2}\left(\mathbf{v}^\top A \mathbf{v}\right) = A_{21}v_1 + A_{12}v_1 + 2A_{22}v_2$

Stack into a column, which is what denominator layout asks for:

$\dfrac{\partial}{\partial \mathbf{v}}\mathbf{v}^\top A \mathbf{v} = \begin{bmatrix} 2A_{11}v_1 + A_{21}v_2 + A_{12}v_2 \\ A_{21}v_1 + A_{12}v_1 + 2A_{22}v_2\end{bmatrix}$   (LHS)

The factor of 2 on the diagonal terms comes from the square; the cross terms contribute $A_{12} + A_{21}$ once each. Hold that thought.

Step 4 — Expand the right side, and compare

Add the two matrices entrywise:

$A^\top + A = \begin{bmatrix} A_{11} & A_{21} \\ A_{12} & A_{22}\end{bmatrix} + \begin{bmatrix} A_{11} & A_{12} \\ A_{21} & A_{22}\end{bmatrix} = \begin{bmatrix} 2A_{11} & A_{12} + A_{21} \\ A_{12} + A_{21} & 2A_{22}\end{bmatrix}$

This matrix is symmetric, which is worth noticing: $A^\top + A$ is always symmetric, for any $A$. Now multiply by $\mathbf{v}$:

$(A^\top + A)\mathbf{v} = \begin{bmatrix} 2A_{11} & A_{12}+A_{21} \\ A_{12}+A_{21} & 2A_{22}\end{bmatrix}\begin{bmatrix} v_1 \\ v_2\end{bmatrix} = \begin{bmatrix} 2A_{11}v_1 + (A_{12} + A_{21})v_2 \\ (A_{12}+A_{21})v_1 + 2A_{22}v_2\end{bmatrix}$   (RHS)

Compare (LHS) and (RHS) entry by entry:

Entry(LHS)(RHS)Same?
1$2A_{11}v_1 + A_{21}v_2 + A_{12}v_2$$2A_{11}v_1 + (A_{12}+A_{21})v_2$✓
2$A_{21}v_1 + A_{12}v_1 + 2A_{22}v_2$$(A_{12}+A_{21})v_1 + 2A_{22}v_2$✓

Identical after factoring. ■

Step 5 — The general case, for any $n$

The handout asks whether the result holds in general. It does, and the index-notation proof is three lines once you have seen the $2\times2$ case.

Write the quadratic form as a double sum:

$\mathbf{v}^\top A \mathbf{v} = \displaystyle\sum_{i=1}^{n}\sum_{j=1}^{n} v_i A_{ij} v_j$

Differentiate with respect to $v_k$. The variable $v_k$ appears in a term $v_i A_{ij} v_j$ exactly when $i = k$ or $j = k$, so split the sum into three disjoint groups — terms with $i=k, j \neq k$; terms with $j = k, i \neq k$; and the single term $i = j = k$:

$\dfrac{\partial}{\partial v_k}\sum_{i,j} v_i A_{ij}v_j = \underbrace{\sum_{j \neq k} A_{kj}v_j}_{i=k} \; + \; \underbrace{\sum_{i\neq k} v_i A_{ik}}_{j=k} \; + \; \underbrace{2A_{kk}v_k}_{i=j=k}$

The last term carries a 2 because $v_k A_{kk} v_k = A_{kk}v_k^2$. Now fold one $A_{kk}v_k$ into each of the first two sums, which restores their full ranges:

$= \sum_{j=1}^{n} A_{kj}v_j + \sum_{i=1}^{n} A_{ik}v_i = (A\mathbf{v})_k + (A^\top \mathbf{v})_k = \left((A + A^\top)\mathbf{v}\right)_k$

Since this holds for every $k$, the full column is $(A^\top + A)\mathbf{v}$. ■

Recognising the two sums is the only step that needs care: $\sum_j A_{kj}v_j$ is the $k$-th entry of $A\mathbf{v}$ (row $k$ of $A$ dotted with $\mathbf{v}$), while $\sum_i A_{ik}v_i$ is the $k$-th entry of $A^\top \mathbf{v}$ (column $k$ of $A$ dotted with $\mathbf{v}$).

Numerical verification. With $A = \begin{bmatrix} 2 & -3 \\ 5 & 1\end{bmatrix}$ and $\mathbf{v} = (1.3, -0.7)$, a central-difference gradient gives $(3.8,\ 1.2)$ and $(A^\top + A)\mathbf{v}$ gives $(3.8,\ 1.2)$. A random $4 \times 4$ instance agrees to within $4 \times 10^{-10}$, which is numerical-differentiation noise.

Answer & the takeaway

$\boxed{\dfrac{\partial}{\partial \mathbf{v}}\mathbf{v}^\top A \mathbf{v} = (A^\top + A)\mathbf{v}} \qquad \text{for any } A \in \mathbb{R}^{n\times n},\ \mathbf{v} \in \mathbb{R}^n$

The corollary you will use constantly

When $A$ is symmetric ($A^\top = A$), the formula collapses to $$\frac{\partial}{\partial \mathbf{v}}\mathbf{v}^\top A \mathbf{v} = 2A\mathbf{v},$$ which is the exact analogue of $\frac{d}{dv}av^2 = 2av$. And the $A$ you meet in linear regression is $X^\top X$, which is symmetric, since $(X^\top X)^\top = X^\top X$. So in practice you nearly always use the $2A\mathbf{v}$ form — but you must know the general form to justify it.

Takeaways.

  • Work from both ends. Expanding the target alongside the source is what makes this proof mechanical instead of a guessing game.
  • Only $A_{12} + A_{21}$ ever appears. That is why the answer involves $A + A^\top$: a quadratic form cannot distinguish $A$ from its symmetric part, so neither can its derivative.
  • Shape-check at the start. Confirming both sides are $n \times 1$ before computing anything is thirty seconds that protects the whole derivation.

Technique: proving a matrix-calculus identity by expansion, in both index and explicit form. Read: Chapter 8, where this identity produces the normal equations — which is exactly Problem 4.4.

4.4  Take it back now: the closed-form solution for linear regression

Problem 4.4Use the identities to derive the normal equations

The linear-regression objective is

$J(\boldsymbol{\theta}) = \dfrac{1}{N}\lVert \mathbf{y} - X\boldsymbol{\theta}\rVert_2^2$

which expands to

$J(\boldsymbol{\theta}) = \dfrac{1}{N}\left(\mathbf{y}^\top \mathbf{y} - 2\boldsymbol{\theta}^\top X^\top \mathbf{y} + \boldsymbol{\theta}^\top X^\top X \boldsymbol{\theta}\right)$

(1) Using $\dfrac{\partial}{\partial \mathbf{v}}\mathbf{v}^\top A \mathbf{v} = (A^\top + A)\mathbf{v}$ and $\dfrac{\partial\, \mathbf{v}^\top \mathbf{u}}{\partial \mathbf{v}} = \mathbf{u}$, find $\nabla J(\boldsymbol{\theta})$. (2) Solve for the minimiser.

Step 1 — What is actually being asked?

This is the payoff problem: the two identities you just proved are exactly the two you need, and nothing else is required. Identify which identity applies to which term before differentiating:

TermDepends on $\boldsymbol{\theta}$?Which identity
$\mathbf{y}^\top \mathbf{y}$noderivative is $\mathbf{0}$
$-2\boldsymbol{\theta}^\top X^\top \mathbf{y}$linearly$\partial\, \mathbf{v}^\top\mathbf{u}/\partial\mathbf{v} = \mathbf{u}$ with $\mathbf{u} = X^\top\mathbf{y}$
$\boldsymbol{\theta}^\top X^\top X \boldsymbol{\theta}$quadratically$(A^\top + A)\mathbf{v}$ with $A = X^\top X$

Shapes, with $X \in \mathbb{R}^{N \times M}$, $\mathbf{y} \in \mathbb{R}^{N\times1}$, $\boldsymbol{\theta} \in \mathbb{R}^{M \times 1}$: $X^\top \mathbf{y}$ is $M \times 1$, $X^\top X$ is $M \times M$, and $\nabla J$ must be $M \times 1$. Everything below should stay $M \times 1$.

Step 2 — (1) Differentiate term by term

$\nabla J(\boldsymbol{\theta}) = \dfrac{\partial}{\partial \boldsymbol{\theta}}\dfrac{1}{N}\left(\mathbf{y}^\top\mathbf{y} - 2\boldsymbol{\theta}^\top X^\top \mathbf{y} + \boldsymbol{\theta}^\top X^\top X \boldsymbol{\theta}\right)$

Term 1: $\mathbf{y}^\top \mathbf{y}$ contains no $\boldsymbol{\theta}$, so its derivative is the zero vector.

Term 2: apply $\partial\,\mathbf{v}^\top\mathbf{u}/\partial\mathbf{v} = \mathbf{u}$ with $\mathbf{v} = \boldsymbol{\theta}$ and $\mathbf{u} = X^\top \mathbf{y}$, keeping the $-2$:

$\dfrac{\partial}{\partial\boldsymbol{\theta}}\left(-2\boldsymbol{\theta}^\top X^\top \mathbf{y}\right) = -2X^\top \mathbf{y}$

Term 3: apply $(A^\top + A)\mathbf{v}$ with $A = X^\top X$:

$\dfrac{\partial}{\partial\boldsymbol{\theta}}\left(\boldsymbol{\theta}^\top X^\top X \boldsymbol{\theta}\right) = \left((X^\top X)^\top + X^\top X\right)\boldsymbol{\theta}$

Now simplify using the fact that $X^\top X$ is symmetric: $(X^\top X)^\top = X^\top (X^\top)^\top = X^\top X$. So the bracket is $2X^\top X$ and the term is $2X^\top X \boldsymbol{\theta}$.

Assembling:

$\nabla J(\boldsymbol{\theta}) = \dfrac{1}{N}\left(\mathbf{0} - 2X^\top \mathbf{y} + 2X^\top X\boldsymbol{\theta}\right) = \boxed{\dfrac{2}{N}\left(X^\top X\boldsymbol{\theta} - X^\top \mathbf{y}\right)}$

Shape check: $X^\top X \boldsymbol{\theta}$ is $(M\times M)(M\times1) = M \times 1$; $X^\top \mathbf{y}$ is $M \times 1$. Their difference is $M \times 1$. ✓

Step 3 — (2) Set the gradient to zero and solve

$J$ is convex in $\boldsymbol{\theta}$ (a positive multiple of a squared norm of an affine function), so a stationary point is a global minimum. Set $\nabla J = \mathbf{0}$:

$\dfrac{2}{N}\left(X^\top X \boldsymbol{\theta} - X^\top \mathbf{y}\right) = \mathbf{0}$

The scalar $2/N$ is non-zero, so divide it out:

$X^\top X \boldsymbol{\theta} - X^\top \mathbf{y} = \mathbf{0} \qquad \Longrightarrow \qquad X^\top X \boldsymbol{\theta} = X^\top \mathbf{y}$

These are the normal equations. Left-multiply by $(X^\top X)^{-1}$, assuming it exists:

$\boxed{\boldsymbol{\theta} = \left(X^\top X\right)^{-1} X^\top \mathbf{y}}$

Shape check: $(M\times M)(M \times N)(N\times1) = M\times1$. ✓

The caveat the derivation hides

The last step needs $X^\top X$ to be invertible, which fails when $X$ has linearly dependent columns — duplicated features, a feature that is a linear combination of others, or more features than examples ($M > N$). In that case the normal equations still hold but have infinitely many solutions, and the inverse does not exist. Two fixes: use a pseudoinverse, or add L2 regularisation, which makes $X^\top X + \lambda I$ invertible for any $\lambda > 0$. That second fix is Problem 5.6.

Numerical verification. On a 4-point dataset with $X = [\mathbf{1}, (1,2,3,4)]$ and $\mathbf{y} = (2,\ 2.9,\ 4.2,\ 4.9)$, the closed form gives $\boldsymbol{\theta} = (1.0,\ 1.0)$ exactly, and the numerical gradient of $J$ at that $\boldsymbol{\theta}$ is zero to 10 decimal places — confirming it is a stationary point, as the derivation claims.

Answer & the takeaway

(1) $\nabla J(\boldsymbol{\theta}) = \frac{2}{N}\left(X^\top X \boldsymbol{\theta} - X^\top \mathbf{y}\right)$.   (2) $\boldsymbol{\theta} = (X^\top X)^{-1}X^\top \mathbf{y}$.

Takeaways.

  • This is why Problem 4.3 exists. The entire vector-calculus recitation is scaffolding for this one derivation, and the derivation is the reason linear regression has a closed form at all — something almost no other model in this course has. Logistic regression, by contrast, has no closed form, which is why Chapter 9 exists.
  • Symmetry of $X^\top X$ does real work. Without it you would be stuck with $\left((X^\top X)^\top + X^\top X\right)\boldsymbol{\theta}$ and could not simplify. Expect to be asked to justify that step.
  • Shape-check every line. Four shape checks appear above and each one would have caught a transposition error.

Technique: applying matrix-calculus identities to derive a closed-form estimator. Read: Chapter 8 — Linear regression for the full treatment including the invertibility conditions.

Six problems. The multiclass walkthrough and the $K=2$ reduction are the two that reward preparation most — the reduction in particular is an exercise the lecture notes also set, which is usually a strong signal.

5.1  Definitions batch: from linear regression to softmax

Problem 5.1Six definitions that build on each other

Define: (a) linear regression, (b) the logistic function, (c) logistic regression, (d) one-hot encoding, (e) multiclass logistic regression — both one-vs-all and softmax, (f) cross-entropy loss.

Step 1 — What is actually being asked?

These six are one idea stretched in two directions. Hold the structure, not six separate cards:

linear score $\to$ squash to a probability $\to$ generalise the squash to $K$ classes $\to$ score it with cross-entropy

Throughout, assume $\mathbf{x}$ has been augmented with a leading 1 so that $\boldsymbol{\theta}^\top \mathbf{x}$ includes a bias term and no separate intercept is needed. Also throughout: a superscript $(i)$ indexes the example, not a power. $\mathbf{x}^{(i)}$ is the $i$-th training input.

Step 2 — (a) Linear regression and (b) the logistic function
Linear regression

Given $\mathcal{D} = \{(\mathbf{x}^{(1)}, y^{(1)}), \dots, (\mathbf{x}^{(N)}, y^{(N)})\}$ with $\mathbf{x}^{(i)} \in \mathbb{R}^M$ and $y^{(i)} \in \mathbb{R}$, the hypothesis is $$\hat{y}^{(i)} = h_{\boldsymbol\theta}(\mathbf{x}^{(i)}) = \boldsymbol{\theta}^\top \mathbf{x}^{(i)}, \qquad \boldsymbol{\theta} \in \mathbb{R}^M.$$ The target is real-valued, so this is regression.

Logistic (sigmoid) function

$$g_{\text{logistic}}(z) = \frac{1}{1 + e^{-z}}$$ a member of the S-shaped sigmoid family. Properties: strictly increasing; range $(0,1)$ exclusive; $g(0) = \tfrac12$; $g(-z) = 1 - g(z)$; and smooth everywhere, which is what makes gradient-based training possible — a hard threshold has zero gradient almost everywhere and is useless to optimise.

The derivative is worth knowing by heart: $g'(z) = g(z)\left(1 - g(z)\right)$. It is maximal ($= \tfrac14$) at $z = 0$ and vanishes as $|z| \to \infty$, which is the saturation that makes very confident logistic units learn slowly.

Step 3 — (c) Logistic regression and (d) one-hot encoding
Logistic regression

Used for classification, but it outputs a real number interpreted as a probability: $$\hat{y}^{(i)} = h_{\boldsymbol\theta}(\mathbf{x}^{(i)}) = P(Y = 1 \mid \mathbf{x}^{(i)}; \boldsymbol{\theta}) = \frac{1}{1 + e^{-\boldsymbol{\theta}^\top \mathbf{x}^{(i)}}}$$ where $Y$ is a binary random variable. Capital $Y$ signals a random variable; lowercase $y$ is an observed value.

So logistic regression is "linear regression's score, pushed through a sigmoid, and read as $P(Y=1)$". The complement is automatic:

$P(Y = 0 \mid \mathbf{x};\boldsymbol\theta) = 1 - \dfrac{1}{1+e^{-z}} = \dfrac{e^{-z}}{1+e^{-z}}, \qquad z = \boldsymbol\theta^\top\mathbf{x}$

One-hot encoding

A vector representation of a class index. With $K$ classes, class $n$ becomes $\mathbf{u} \in \{0,1\}^K$ with $u_n = 1$ and $u_i = 0$ for all $i \neq n$. Example: $K = 5$, $n = 3$ gives $\mathbf{u} = [0, 0, 1, 0, 0]^\top$.

Why bother: class labels are nominal, and the integers $1,2,3$ carry an arithmetic the classes do not have. Encoding class 3 as the number 3 implies it is "between" 2 and 4 and three times class 1 — nonsense for chocolate, vanilla, strawberry. One-hot removes that false structure, and it also makes the cross-entropy sum in (f) collapse to a single term.

Step 4 — (e) Two ways to do $K$ classes

One-vs-all. Train $K$ independent binary logistic models. For each $k$, relabel the data so class $k$ is positive and everything else is negative, fit $\boldsymbol\theta_k$, and obtain $P(Y_k = 1 \mid \mathbf{x}; \boldsymbol\theta_k)$. Predict by $\hat{y} = \arg\max_k P(Y_k = 1 \mid \mathbf{x};\boldsymbol\theta_k)$.

Two weaknesses, both worth being able to name:

  • It ignores the relationship between classes — each model is fit blind to the others.
  • It loses the probabilistic interpretation. The $K$ outputs are probabilities from $K$ unrelated models and in general do not sum to 1, so the argmax is a vote, not a posterior.

Softmax (multinomial logistic regression). One model, $K$ parameter vectors, tied together. Define $K$ linear scores $z_k = \boldsymbol\theta_k^\top \mathbf{x}$ and normalise them jointly:

$g_{\text{softmax}}(\mathbf{z}) = \dfrac{1}{\sum_{k=1}^{K} e^{z_k}}\begin{bmatrix} e^{z_1} \\ e^{z_2} \\ \vdots \\ e^{z_K}\end{bmatrix}$

Every entry is in $(0,1)$ and they sum to exactly 1, so the output is a probability distribution. Stacking the parameter vectors as rows of a matrix:

$\Theta = \begin{bmatrix} -\!\!-\ \boldsymbol\theta_1^\top\ -\!\!- \\ -\!\!-\ \boldsymbol\theta_2^\top\ -\!\!- \\ \vdots \\ -\!\!-\ \boldsymbol\theta_K^\top\ -\!\!-\end{bmatrix}, \qquad \mathbf{z} = \Theta \mathbf{x}, \qquad \hat{\mathbf{y}} = h_\Theta(\mathbf{x}) = g_{\text{softmax}}(\Theta\mathbf{x})$

with $\hat{y}_k = P(Y_k = 1 \mid \mathbf{x}; \Theta)$. Shapes: $\Theta$ is $K \times M$, $\mathbf{x}$ is $M \times 1$, so $\mathbf{z}$ and $\hat{\mathbf{y}}$ are $K \times 1$.

Step 5 — (f) Cross-entropy loss
Cross-entropy

For $N$ samples and $K$ classes, with $y^{(i)}_k$ the one-hot true label and $\hat{y}^{(i)}_k$ the predicted probability, $$J(\Theta) = -\frac{1}{N}\sum_{i=1}^{N}\sum_{k=1}^{K} y^{(i)}_k \log\!\left(\hat{y}^{(i)}_k\right).$$

It measures how far the predicted distribution is from the true one. The key simplification, which is what makes it cheap:

The inner sum collapses

$\mathbf{y}^{(i)}$ is one-hot, so exactly one $y^{(i)}_k$ equals 1 and the rest are 0. Every term in the inner sum but one is multiplied by zero. So $$J(\Theta) = -\frac{1}{N}\sum_{i=1}^{N} \log \hat{y}^{(i)}_{k_i}$$ where $k_i$ is sample $i$'s true class. In practice: take the predicted probability of the correct class, log it, negate, average. That is the whole computation, and it is what Problem 5.3 does by hand.

Properties: $J \ge 0$; $J \to 0$ as the model gets the right class probability $\to 1$; and $J \to \infty$ if the model assigns probability $\to 0$ to a correct class. That last property is the point — cross-entropy punishes confident wrongness unboundedly, where accuracy would merely count it as one error.

5.2  Quick logistic regression questions

Problem 5.2Linear vs logistic, and the sign of $\boldsymbol\theta^\top\mathbf{x}$

(1) List differences between linear and logistic regression. When would you use logistic instead?

(2) $g(z)$ lies strictly in $(0,1)$. What probability distribution does it represent?

(3) Let $\mathbf{x} \in \mathbb{R}^3$ and $\boldsymbol\theta = \begin{bmatrix} 1 \\ 4 \\ 3\end{bmatrix}$. (a) Give an $\mathbf{x}$ with $\boldsymbol\theta^\top\mathbf{x} > 0$ and compute $g(\boldsymbol\theta^\top\mathbf{x})$. (b) Give an $\mathbf{x}$ with $\boldsymbol\theta^\top\mathbf{x} = 0$ and compute $g(\boldsymbol\theta^\top\mathbf{x})$. Then explain the general relationship between $g(\boldsymbol\theta^\top\mathbf{x})$ and $\boldsymbol\theta^\top\mathbf{x}$.

Step 1 — What is actually being asked?

Part 3 is secretly the important one: it is building, from arithmetic, the fact that $\boldsymbol\theta^\top\mathbf{x} = 0$ is the decision boundary. Everything else in part 3 is there so that the boundary falls out of numbers rather than being asserted.

Note that part 3 asks you to construct an $\mathbf{x}$, so there are many right answers. Pick the easiest ones.

When to use logistic: whenever the label is binary (or categorical, via softmax). Three concrete reasons linear regression is the wrong tool for a 0/1 label:

  • It predicts values outside $[0,1]$, which cannot be probabilities.
  • Squared error on a 0/1 target penalises confidently-correct predictions that overshoot, which is incoherent.
  • It is badly destabilised by outliers in $\mathbf{x}$, because a far-away point drags the whole fitted line and so moves the implied threshold.

The honest symmetry: both are linear in the parameters and both have linear decision structure. Logistic regression's boundary is a hyperplane, just like linear regression's fit — the sigmoid changes the output, not the geometry of the boundary.

Step 3 — (2) Which distribution

A Bernoulli distribution over the binary class variable $Y$, conditioned on $\mathbf{x}$:

$P(Y = 1 \mid \mathbf{x}) = \dfrac{1}{1+e^{-z}}, \qquad P(Y = 0 \mid \mathbf{x}) = 1 - \dfrac{1}{1+e^{-z}} = \dfrac{e^{-z}}{1+e^{-z}}$

with $z = \boldsymbol\theta^\top \mathbf{x}$. The two probabilities sum to 1 by construction, and the open interval $(0,1)$ is exactly right: a logistic model is never absolutely certain, which matters because $\log 0$ in the cross-entropy would be infinite.

A neat identity worth knowing: dividing the two gives $\dfrac{P(Y=1\mid\mathbf{x})}{P(Y=0\mid\mathbf{x})} = e^{z}$, so $\log \dfrac{P(Y=1\mid\mathbf{x})}{P(Y=0\mid\mathbf{x})} = \boldsymbol\theta^\top\mathbf{x}$. The model is linear in the log-odds. That is the cleanest one-line characterisation of logistic regression there is.

Step 4 — (3) Construct the inputs and read off the boundary

(a) Want $\boldsymbol\theta^\top\mathbf{x} > 0$. The simplest choice is $\mathbf{x} = (1, 1, 1)^\top$:

$\boldsymbol\theta^\top\mathbf{x} = 1(1) + 4(1) + 3(1) = 8 > 0$

$g(8) = \dfrac{1}{1+e^{-8}} = \mathbf{0.99966}$

Very close to 1 — the model is confidently predicting class 1.

(b) Want $\boldsymbol\theta^\top\mathbf{x} = 0$. Solve $x_1 + 4x_2 + 3x_3 = 0$; one easy solution is $\mathbf{x} = (7, -1, -1)^\top$:

$\boldsymbol\theta^\top\mathbf{x} = 7 - 4 - 3 = 0, \qquad g(0) = \dfrac{1}{1+e^{0}} = \dfrac{1}{2} = \mathbf{0.5}$

The general relationship. $g$ is strictly increasing with $g(0) = \tfrac12$, so the sign of $z$ determines which side of a half you land on:

Answer & the takeaway
The decision boundary

$$\boldsymbol\theta^\top \mathbf{x} = 0$$ is the decision boundary of logistic regression. It is a hyperplane — linear in $\mathbf{x}$ — even though the model's output is a nonlinear function of $\mathbf{x}$. The sigmoid is monotone, so thresholding $g(z)$ at $0.5$ is identical to thresholding $z$ at 0, and the nonlinearity has no effect whatever on where the boundary sits. It only changes the confidence attached to each side.

5.4  $K = 2$: multiclass softmax reduces to binary logistic regression

Problem 5.4Derive the reduction completely

Show the following two are equivalent. Equation (1) is $K=2$ softmax regression; equation (2) is binary logistic regression.

$\text{(1)}\quad P(Y_k = 1 \mid \mathbf{x}^{(i)}; \Theta) = \dfrac{\exp\!\left(\boldsymbol\theta_k^\top\mathbf{x}^{(i)}\right)}{\sum_{l=1}^{2}\exp\!\left(\boldsymbol\theta_l^\top\mathbf{x}^{(i)}\right)}$

$\text{(2)}\quad P(Y = k \mid \mathbf{x}^{(i)};\boldsymbol\theta_\alpha) = \begin{cases} \dfrac{1}{1+\exp\!\left(-\boldsymbol\theta_\alpha^\top\mathbf{x}^{(i)}\right)} & k = 1 \\[8pt] \dfrac{\exp\!\left(-\boldsymbol\theta_\alpha^\top\mathbf{x}^{(i)}\right)}{1+\exp\!\left(-\boldsymbol\theta_\alpha^\top\mathbf{x}^{(i)}\right)} & k = 2\end{cases}$

You will need to find what $\boldsymbol\theta_\alpha$ must be in terms of $\boldsymbol\theta_1$ and $\boldsymbol\theta_2$.

Step 1 — What is actually being asked?

The two models look different: (1) has two parameter vectors, (2) has one. Showing equivalence therefore means doing two things:

  1. Algebraically transform (1) into the shape of (2).
  2. Identify $\boldsymbol\theta_\alpha$ in terms of $\boldsymbol\theta_1$ and $\boldsymbol\theta_2$. This is the actual content — it tells you that $K=2$ softmax has one redundant parameter vector's worth of freedom.

The single algebraic move that does it: divide numerator and denominator by the numerator. That is the whole trick, and it is worth recognising on sight because it also derives the log-odds form of logistic regression.

Step 2 — Write out (1) for both classes

With $K = 2$ the softmax vector is

$\begin{bmatrix} P(Y_1 = 1 \mid \mathbf{x}^{(i)};\Theta) \\ P(Y_2 = 1\mid\mathbf{x}^{(i)};\Theta)\end{bmatrix} = \dfrac{1}{\exp\!\left(\boldsymbol\theta_1^\top\mathbf{x}^{(i)}\right) + \exp\!\left(\boldsymbol\theta_2^\top\mathbf{x}^{(i)}\right)}\begin{bmatrix} \exp\!\left(\boldsymbol\theta_1^\top\mathbf{x}^{(i)}\right) \\ \exp\!\left(\boldsymbol\theta_2^\top\mathbf{x}^{(i)}\right)\end{bmatrix}$

Both entries share the same denominator, which is why the next step works on either one.

Step 3 — Divide through by the numerator

Take the $k=1$ entry and divide top and bottom by $\exp(\boldsymbol\theta_1^\top\mathbf{x}^{(i)})$, which is strictly positive so this is always legal:

$P(Y_1 = 1\mid\mathbf{x}^{(i)};\Theta) = \dfrac{\exp\!\left(\boldsymbol\theta_1^\top\mathbf{x}^{(i)}\right)}{\exp\!\left(\boldsymbol\theta_1^\top\mathbf{x}^{(i)}\right) + \exp\!\left(\boldsymbol\theta_2^\top\mathbf{x}^{(i)}\right)}$

$= \dfrac{\exp\!\left(\boldsymbol\theta_1^\top\mathbf{x}^{(i)}\right) \big/ \exp\!\left(\boldsymbol\theta_1^\top\mathbf{x}^{(i)}\right)}{\left[\exp\!\left(\boldsymbol\theta_1^\top\mathbf{x}^{(i)}\right) + \exp\!\left(\boldsymbol\theta_2^\top\mathbf{x}^{(i)}\right)\right]\big/ \exp\!\left(\boldsymbol\theta_1^\top\mathbf{x}^{(i)}\right)}$

$= \dfrac{1}{1 + \exp\!\left(\boldsymbol\theta_2^\top\mathbf{x}^{(i)}\right)\big/\exp\!\left(\boldsymbol\theta_1^\top\mathbf{x}^{(i)}\right)}$

Now use $e^{a}/e^{b} = e^{a-b}$, and pull the $\mathbf{x}^{(i)}$ out of the difference:

$= \dfrac{1}{1 + \exp\!\left(\boldsymbol\theta_2^\top\mathbf{x}^{(i)} - \boldsymbol\theta_1^\top\mathbf{x}^{(i)}\right)} = \dfrac{1}{1 + \exp\!\left(\left(\boldsymbol\theta_2 - \boldsymbol\theta_1\right)^\top\mathbf{x}^{(i)}\right)}$

The step $\boldsymbol\theta_2^\top\mathbf{x} - \boldsymbol\theta_1^\top\mathbf{x} = (\boldsymbol\theta_2 - \boldsymbol\theta_1)^\top\mathbf{x}$ is just linearity of the dot product, but it is the step that makes the whole thing work: two parameter vectors have collapsed into one.

Step 4 — Define $\boldsymbol\theta_\alpha$ and match (2)

We have $\dfrac{1}{1 + \exp\!\left((\boldsymbol\theta_2 - \boldsymbol\theta_1)^\top\mathbf{x}^{(i)}\right)}$ and we want $\dfrac{1}{1 + \exp\!\left(-\boldsymbol\theta_\alpha^\top\mathbf{x}^{(i)}\right)}$. Matching the exponents:

$-\boldsymbol\theta_\alpha^\top\mathbf{x}^{(i)} = (\boldsymbol\theta_2 - \boldsymbol\theta_1)^\top\mathbf{x}^{(i)} \quad \text{for all } \mathbf{x}^{(i)}$

which forces

$\boxed{\boldsymbol\theta_\alpha = -(\boldsymbol\theta_2 - \boldsymbol\theta_1) = \boldsymbol\theta_1 - \boldsymbol\theta_2}$

With that definition,

$P(Y_1 = 1 \mid \mathbf{x}^{(i)};\Theta) = \dfrac{1}{1+\exp\!\left(-\boldsymbol\theta_\alpha^\top\mathbf{x}^{(i)}\right)}$

which is exactly the $k=1$ case of (2). For $k = 2$, use the fact that the two softmax outputs sum to 1:

$P(Y_2 = 1\mid\mathbf{x}^{(i)};\Theta) = 1 - \dfrac{1}{1+\exp\!\left(-\boldsymbol\theta_\alpha^\top\mathbf{x}^{(i)}\right)} = \dfrac{\left(1 + \exp(-\boldsymbol\theta_\alpha^\top\mathbf{x}^{(i)})\right) - 1}{1+\exp\!\left(-\boldsymbol\theta_\alpha^\top\mathbf{x}^{(i)}\right)}$

$= \dfrac{\exp\!\left(-\boldsymbol\theta_\alpha^\top\mathbf{x}^{(i)}\right)}{1+\exp\!\left(-\boldsymbol\theta_\alpha^\top\mathbf{x}^{(i)}\right)}$

which is exactly the $k = 2$ case of (2). Both cases match, so the models are equivalent. ■

Step 5 — Why this works: the redundancy, made explicit

The reduction is not a coincidence; it is a symptom of something true for every $K$.

Softmax is over-parameterised

Add the same vector $\mathbf{c}$ to every $\boldsymbol\theta_k$. Then every score shifts by the same amount $\mathbf{c}^\top\mathbf{x}$, and by the shift-invariance identity from Problem 5.3 the softmax output is unchanged: $$g_{\text{softmax}}\!\left((\Theta + \mathbf{1}\mathbf{c}^\top)\mathbf{x}\right) = g_{\text{softmax}}(\Theta\mathbf{x}).$$

Numerically verified: with $\boldsymbol\theta_1 = (0.4, -1.2, 0.9)$, $\boldsymbol\theta_2 = (-0.3, 0.5, 2.0)$ and $\mathbf{x} = (1,2,-1)$, the softmax is $(0.16798161,\ 0.83201839)$; adding $\mathbf{c} = (1.7, -0.2, 0.6)$ to both parameter vectors gives $(0.16798161,\ 0.83201839)$ — identical to 8 decimal places.

So softmax regression has $M$ redundant degrees of freedom: the whole family $\{\boldsymbol\theta_k + \mathbf{c}\}$ represents the same model. A standard way to remove the redundancy is to fix one parameter vector at zero, say $\boldsymbol\theta_2 = \mathbf{0}$. Do that in the $K=2$ case and $\boldsymbol\theta_\alpha = \boldsymbol\theta_1 - \mathbf{0} = \boldsymbol\theta_1$ — one parameter vector, which is precisely binary logistic regression.

Numerical confirmation of the reduction itself: with the same $\boldsymbol\theta_1, \boldsymbol\theta_2$ as above, the two-class softmax probability of class 1 and the sigmoid $1/(1+e^{-\boldsymbol\theta_\alpha^\top\mathbf{x}})$ with $\boldsymbol\theta_\alpha = \boldsymbol\theta_1 - \boldsymbol\theta_2$ agree exactly — to within $10^{-12}$ — at $\mathbf{x} = (1,2,-1)$, $(1,-0.5,3)$ and $(1,0,0)$, giving $0.1679816149$, $0.1480471980$ and $0.6681877722$ respectively.

A consequence worth stating: because only the difference $\boldsymbol\theta_1 - \boldsymbol\theta_2$ affects the output, the individual values of $\boldsymbol\theta_1$ and $\boldsymbol\theta_2$ are not identifiable from data. Two training runs can land on wildly different $\Theta$ matrices and define the identical classifier. (Adding L2 regularisation breaks the tie, because among all equivalent $\Theta$ it prefers the one of smallest norm — another reason regularisation is standard practice.)

Answer & the takeaway

Result: $K=2$ softmax regression is binary logistic regression with

$\boldsymbol\theta_\alpha = \boldsymbol\theta_1 - \boldsymbol\theta_2.$

The derivation is one move — divide numerator and denominator by the numerator — followed by $e^a/e^b = e^{a-b}$ and the linearity of the dot product.

Takeaways.

  • Softmax generalises the sigmoid, not the other way round. You can always recover the sigmoid by setting $K=2$; so anything true of softmax is true of logistic regression as a special case, which is why the lecture notes derive the softmax gradient once and reuse it.
  • The divide-by-the-numerator move is the standard way to turn a ratio of exponentials into a sigmoid, and it appears again when you derive the log-odds form.
  • Only differences of parameter vectors matter. That is what makes the reduction possible and it is also why softmax parameters are not individually interpretable.

Technique: deriving a model reduction, and recognising over-parameterisation. Read: Chapter 11 — the same exercise appears there, and Chapter 12 explains why regularisation resolves the non-identifiability.

5.5  Regularization definitions: L0, L1, L2

Problem 5.5Why regularize, and what each norm does

Explain why we regularize, then define the L0, L1 and L2 norms and compare their properties.

Step 1 — What is actually being asked?

Three things, and the comparison is what earns the marks: the definitions are one line each, but "which one would you use and why" is the question that follows on an exam.

Frame: regularization adds a penalty on the size of $\boldsymbol\theta$ to the objective, so that minimising it trades fit against simplicity. The norm you pick decides what "simple" means.

Step 2 — Why regularize

A flexible model can fit the training set too closely — memorising it rather than learning the pattern — and then generalises badly. Regularization attacks that directly by penalising complexity, pushing the optimiser towards simpler parameter vectors that do better on unseen data.

The objective becomes

$J_{\text{reg}}(\boldsymbol\theta) = \underbrace{J(\boldsymbol\theta)}_{\text{fit the data}} + \lambda \underbrace{R(\boldsymbol\theta)}_{\text{stay simple}}$

where $\lambda \ge 0$ sets the exchange rate. $\lambda = 0$ recovers the unregularized model; $\lambda \to \infty$ drives $\boldsymbol\theta \to \mathbf{0}$ and the model predicts a constant. $\lambda$ is a hyperparameter, so it is chosen on a validation set, never on the training set — training error is monotonically increasing in $\lambda$, so training error can only ever tell you to pick $\lambda = 0$.

Step 3 — The three norms
L2 (Euclidean) norm

$$\lVert \mathbf{x}\rVert_2 = \sqrt{\sum_{i=1}^{N} x_i^2}$$ the ordinary straight-line length of the vector. In objectives one almost always uses the squared L2 norm, $\lVert\boldsymbol\theta\rVert_2^2 = \sum_i \theta_i^2$, to avoid the square root — which is both differentiable everywhere and keeps the gradient linear.

L1 norm

$$\lVert\mathbf{x}\rVert_1 = \sum_{i=1}^{N}|x_i|$$ the total absolute magnitude — "taxicab" distance.

L0 "norm"

$$\lVert\mathbf{x}\rVert_0 = \sum_{i=1}^{N}\mathbb{1}\!\left[x_i \neq 0\right]$$ the count of non-zero entries, where $\mathbb{1}[\cdot]$ is the indicator function. Sometimes called the counting norm; it is not actually a norm, since it is not homogeneous ($\lVert 2\mathbf{x}\rVert_0 = \lVert\mathbf{x}\rVert_0$, not $2\lVert\mathbf{x}\rVert_0$).

Quick worked comparison on $\mathbf{x} = (3, 0, -4)$:   $\lVert\mathbf{x}\rVert_2 = \sqrt{9 + 0 + 16} = 5$;   $\lVert\mathbf{x}\rVert_1 = 3 + 0 + 4 = 7$;   $\lVert\mathbf{x}\rVert_0 = 2$. Note L0 does not change if you scale $\mathbf{x}$ by 100, while the other two scale by 100.

Step 4 — The two properties that decide which one you use

Sparsity. L0 and L1 encourage sparsity — many parameters driven exactly to zero. L2 prefers parameters that are all small but generally none exactly zero.

Why: L2's gradient with respect to $\theta_i$ is $2\theta_i$, which vanishes as $\theta_i \to 0$, so the pressure to shrink disappears just as the parameter approaches zero — it is shrunk but never pinned. L1's gradient is $\mathrm{sign}(\theta_i)$, constant magnitude 1 all the way in, so a parameter whose contribution to the fit is worth less than $\lambda$ is pushed exactly to zero and stays there.

Optimisation. L1 and L2 are tractable to optimise; L0 is not.

  • L2 is differentiable everywhere and convex — the easiest case. With squared error it even keeps a closed-form solution (Problem 5.6).
  • L1 is convex but not differentiable at 0, so it needs subgradients or proximal methods. Still efficiently solvable.
  • L0 is neither convex nor differentiable — it is piecewise constant, so its gradient is zero almost everywhere and carries no information. Minimising it exactly requires combinatorial search over which subset of parameters is non-zero, which is intractable for realistic $M$. This is why L1 is used as a proxy for L0: it is the tightest convex relaxation that still induces sparsity.

The handout's own summary of this, restated: L0 and L1 give sparsity while L2 gives small-but-nonzero; L1 and L2 are optimisable while L0 is not. L1 is the only one in both good columns, which is exactly why it is the standard choice when you want feature selection, and L2 the standard choice when you simply want stability.

5.6  Ridge regression: the closed form with L2 added

Problem 5.6Derive the regularized closed-form solution

Starting from linear regression's objective, add L2 regularization:

$J(\boldsymbol\theta) = \lVert\mathbf{y} - X\boldsymbol\theta\rVert_2^2 + \lambda\lVert\boldsymbol\theta\rVert_2^2$

Determine the closed-form minimiser.

Step 1 — What is actually being asked?

Problem 4.4 again, with one extra term. So: expand, differentiate with the same two identities, set to zero, solve. The only new work is $\partial(\lambda\boldsymbol\theta^\top\boldsymbol\theta)/\partial\boldsymbol\theta$, and one subtle step at the very end where a scalar has to become a matrix.

Note this objective has no $1/N$ factor, unlike Problem 4.4's. That changes nothing structurally — it only rescales what a given $\lambda$ means, which is worth being aware of when comparing $\lambda$ values across formulations.

Step 2 — Expand

Use $\lVert\mathbf{a}\rVert_2^2 = \mathbf{a}^\top\mathbf{a}$ on both terms:

$J(\boldsymbol\theta) = (\mathbf{y} - X\boldsymbol\theta)^\top(\mathbf{y}-X\boldsymbol\theta) + \lambda\boldsymbol\theta^\top\boldsymbol\theta$

Expand the first product, remembering $(X\boldsymbol\theta)^\top = \boldsymbol\theta^\top X^\top$:

$= \mathbf{y}^\top\mathbf{y} - \mathbf{y}^\top X\boldsymbol\theta - \boldsymbol\theta^\top X^\top\mathbf{y} + \boldsymbol\theta^\top X^\top X \boldsymbol\theta + \lambda\boldsymbol\theta^\top\boldsymbol\theta$

The two middle terms are equal: each is a $1\times1$ scalar, and one is the transpose of the other, and a scalar equals its own transpose. So they combine:

$J(\boldsymbol\theta) = \mathbf{y}^\top\mathbf{y} - 2\boldsymbol\theta^\top X^\top\mathbf{y} + \boldsymbol\theta^\top X^\top X\boldsymbol\theta + \lambda\boldsymbol\theta^\top\boldsymbol\theta$

which is Problem 4.4's expansion plus $\lambda\boldsymbol\theta^\top\boldsymbol\theta$. That "a scalar equals its transpose" step is small and is where marks get lost if it is skipped silently.

Step 3 — Differentiate

Term by term, as in 4.4, and for the new term note $\boldsymbol\theta^\top\boldsymbol\theta = \boldsymbol\theta^\top I \boldsymbol\theta$ is a quadratic form with $A = I$, so $(A^\top + A)\boldsymbol\theta = 2I\boldsymbol\theta = 2\boldsymbol\theta$:

TermDerivative
$\mathbf{y}^\top\mathbf{y}$$\mathbf{0}$
$-2\boldsymbol\theta^\top X^\top \mathbf{y}$$-2X^\top\mathbf{y}$
$\boldsymbol\theta^\top X^\top X \boldsymbol\theta$$2X^\top X\boldsymbol\theta$  (using symmetry of $X^\top X$)
$\lambda\boldsymbol\theta^\top\boldsymbol\theta$$2\lambda\boldsymbol\theta$

$\nabla J(\boldsymbol\theta) = -2X^\top\mathbf{y} + 2X^\top X\boldsymbol\theta + 2\lambda\boldsymbol\theta = -2X^\top(\mathbf{y} - X\boldsymbol\theta) + 2\lambda\boldsymbol\theta$

Shape check: every term is $M \times 1$. ✓

Step 4 — Set to zero and solve — watch the last step

$-2X^\top(\mathbf{y} - X\boldsymbol\theta) + 2\lambda\boldsymbol\theta = \mathbf{0}$

Divide by 2 and expand:

$-X^\top\mathbf{y} + X^\top X \boldsymbol\theta + \lambda\boldsymbol\theta = \mathbf{0} \qquad \Longrightarrow \qquad X^\top X \boldsymbol\theta + \lambda\boldsymbol\theta = X^\top\mathbf{y}$

Now factor out $\boldsymbol\theta$. Here is the step that needs care:

$\lambda$ must become $\lambda I$

Writing $\left(X^\top X + \lambda\right)\boldsymbol\theta$ is type-incorrect: $X^\top X$ is an $M \times M$ matrix and $\lambda$ is a scalar, and you cannot add them. What is meant is $\lambda$ times the identity: $$X^\top X \boldsymbol\theta + \lambda I \boldsymbol\theta = \left(X^\top X + \lambda I\right)\boldsymbol\theta.$$ Graders look for the $I$, and the shape-check habit from recitation 4 catches its absence immediately.

$\left(X^\top X + \lambda I\right)\boldsymbol\theta = X^\top \mathbf{y}$

$\boxed{\boldsymbol\theta = \left(X^\top X + \lambda I\right)^{-1}X^\top\mathbf{y}}$

Numerical verification. On the same 4-point dataset as Problem 4.4 with $\lambda = 0.5$, this formula gives $\boldsymbol\theta = (0.7248,\ 1.0738)$, and the numerical gradient of the regularized objective at that point is zero to 9 decimal places. Compare the unregularized solution, $(1.0,\ 1.0)$: the regularized one has smaller total norm, and the intercept has been pulled hardest toward 0, which is the expected behaviour.

Answer & the takeaway

$\boldsymbol\theta = \left(X^\top X + \lambda I\right)^{-1}X^\top\mathbf{y}$

Compare with the unregularized $\boldsymbol\theta = (X^\top X)^{-1}X^\top\mathbf{y}$: regularization adds $\lambda I$ to the matrix being inverted, and nothing else changes. This is why the method is called ridge regression — it adds a ridge along the diagonal.

Takeaways.

  • It fixes invertibility. Problem 4.4's caveat was that $X^\top X$ can be singular — duplicated features, or $M > N$. Adding $\lambda I$ with $\lambda > 0$ makes the matrix strictly positive definite and therefore always invertible. So ridge regression has a unique closed-form solution even when ordinary least squares has none. That is a practical reason to regularize that has nothing to do with overfitting.
  • $\lambda$ interpolates. $\lambda = 0$ recovers OLS; $\lambda \to \infty$ drives $\boldsymbol\theta \to \mathbf{0}$. Choose it on a validation set.
  • Why L2 and not L1 here. $\lVert\boldsymbol\theta\rVert_2^2$ is differentiable, so the gradient is linear in $\boldsymbol\theta$ and the stationarity condition is a linear system with a closed-form answer. L1 is not differentiable at 0, so lasso has no closed form and needs an iterative solver — the exact trade-off Problem 5.5 describes, now visible in the algebra.
  • In practice, do not penalise the bias. The intercept should be free to match the mean of $\mathbf{y}$; standard implementations use $\lambda I$ with a zero in the bias position. The exam version usually ignores this, but it is worth a sentence if you have room.
